什么是大语言模型（LLM）？它的核心训练目标是什么？

🔥 🔥 字节/阿里/腾讯高频
考察点：LLM 的定义与自回归本质
大白话
大模型 = 超级接话机。训练目标就一个：给你上文，猜下一个字。猜多了，语法和知识都学会了。
详细答案
大语言模型是基于海量文本数据训练、参数量通常在十亿级别以上的深度学习模型，底层架构以 Transformer（Decoder-only）为主。它的核心训练目标是"预测下一个 Token"：给定上文，预测最可能的下一个词。通过在海量语料上不断做这件事，模型把语言的语法、知识、逻辑规律压缩进参数里，从而具备理解与生成自然语言的能力，可完成问答、翻译、摘要、代码生成等任务。注意：模型不是"存储了所有知识的数据库"，知识是以参数权重形式编码的。
追问：为什么"预测下一个词"就能学到知识？预训练和人类学习语言有什么类比？

大模型的"参数"是什么？参数量越大一定越好吗？

🔥 🔥 阿里/美团高频
考察点：参数含义与 Scaling 的边界
大白话
参数 = 模型脑子里的数字，存着它学到的规律。越大通常越聪明，但也更费电、更占内存，不是无脑越大越好。
详细答案
参数是模型训练过程中学习到的数值权重（如矩阵里的每个数），是模型存储语言规律与知识的载体。参数量越大，模型的容量越大，能表示更复杂的函数、记住更多统计规律，通常语义理解与推理能力更强，但训练和推理的算力、显存成本也随之上升。参数量大不等于一定好：数据质量差、训练方法不当或架构不合理时，堆参数收益会下降，所以能力提升是"参数+数据+算力"共同作用的结果。
追问：7B、13B、70B 分别需要多少显存才能推理/微调？

什么是 Token？为什么中文和英文的 Token 数量不一样？

🔥 🔥 通用必问
考察点：Token 化基本概念
大白话
Token = 文字碎片。英文常一个词一块，中文常一个字或一个词一块。算钱、算长度都按 Token 数来。
详细答案
Token 是大模型处理文本的最小单位，是文本被分词后的片段。英文场景下 1 个 Token 约等于 0.7~0.8 个单词；中文场景下 1 个 Token 约等于 1~2 个汉字（甚至一个常见词就是一个 Token）。模型的上下文长度限制、API 计费都以 Token 为单位。之所以不用单个字/字符作为单位，是因为分词能大幅缩短序列长度、提升计算效率，同时保留语义完整性。
追问：一个 1000 字的中文文章大约消耗多少 Token？

什么是上下文窗口？超出窗口长度会怎样？

🔥 🔥 腾讯/美团高频
考察点：Context Window 概念与工程应对
大白话
上下文窗口 = 一次能记住多长。超了就像金鱼记忆：前面的忘了，或者干脆报错。
详细答案
上下文窗口指模型单次请求能处理的最大 Token 长度，包含输入的提示词与输出的回复。超出窗口的内容模型无法感知，会出现"失忆"、回答与上文矛盾，或直接报长度超限错误。工程上应对超长文本的手段包括：滑动窗口截断、对历史对话做摘要压缩、分层记忆（长期记忆外置到向量库）、RAG 检索只取相关片段等。
追问：长上下文模型（如 128K）能完全替代 RAG 吗？各自优劣？

大模型和传统 NLP 模型有什么区别？

🔥 🔥 字节高频
考察点：范式对比
大白话
老 NLP：一个任务训一个模型。大模型：一个底座 + 提示词，啥任务都能干。
详细答案
传统 NLP 是"分任务建模"：文本分类、NER、情感分析各训一个模型，依赖大量标注数据和特征工程，模型小、任务单一。大模型是"通用基座"：一个模型通过 Prompt 驱动可覆盖几乎所有任务，海量数据预训练 + 少量标注微调即可适配下游，具备上下文理解、文本生成、逻辑推理等通用能力。区别的核心是：从"为每个任务造专用模型"变成"一个底座 + 提示/微调适配一切任务"。
追问：BERT 和 GPT 分别属于哪一类范式？

Transformer 的核心结构是什么？为什么它能替代 RNN？

🔥 🔥 字节/阿里高频
考察点：Transformer 结构理解
大白话
Transformer 核心是自注意力：每个词看一遍句子里其他词。比 RNN 并行快，长句子也记得住。
详细答案
Transformer 由多头自注意力（MHA）、前馈网络（FFN）、残差连接与层归一化组成，核心是自注意力机制。它能替代 RNN 有两个根本原因：一是并行化，RNN 必须按时间步串行计算（算第 t 步必须等第 t-1 步），而 Transformer 可一次性并行处理整个序列，充分利用 GPU；二是长程依赖，RNN 梯度经多次连乘容易消失，难以建模远距离关系，而注意力机制直接计算任意两个位置的关联，天然擅长捕捉长距离依赖。
追问：Transformer 的复杂度是多少？自注意力的 O(n²) 体现在哪？

自注意力机制（Self-Attention）是如何工作的？为什么要除以 √dk？

🔥 🔥 字节/小米高频（必考题）
考察点：Attention 公式与原理
大白话
自注意力 = 每个词给句子里其他词打分，分高的多参考。除以 √dk 是为了数字别太大炸掉。
详细答案
对输入序列中的每个 Token，通过三个可学习的矩阵投影得到 Q（查询）、K（键）、V（值）。注意力分数 = QKᵀ / √dk，经过 Softmax 归一化成权重，再对 V 加权求和得到输出。除以 √dk 的原因：当向量维度 dk 较大时，Q·K 的内积数值会偏大，Softmax 的梯度会进入饱和区（梯度极小），除以 √dk 可以把内积方差拉回 1 的量级，让 Softmax 梯度更稳定，训练更容易收敛。
追问：为什么 Q 和 K 的维度要一致？Softmax 之前为什么要做 Mask？

多头注意力（MHA）为什么比单头好？MHA、GQA、MQA、MLA 有什么区别？

🔥 🔥 阿里/腾讯高频
考察点：注意力变体演进
大白话
多头 = 同时从多个角度看句子。GQA/MQA/MLA 都是省显存的变体，少存几份 KV。
详细答案
多头注意力把注意力计算拆成多个"头"，每个头在不同子空间学习不同的关注模式（语法、语义、指代等），最后拼接，表达能力更强。MHA（多头）：每个头独立的 K/V，效果最好但 KV Cache 显存最大；MQA（多查询）：所有头共享一份 K/V，显存最省但效果略降；GQA（分组查询）：把头分组，组内共享 K/V，是 MHA 和 MQA 的折中，Llama-2/3 采用；MLA（多头潜在注意力）：DeepSeek 提出，对 KV 做低秩压缩，进一步省显存且效果不降。
追问：KV Cache 显存优化为什么是推理优化的重点？

位置编码有哪几种？为什么 RoPE 成为主流？

🔥 🔥 大厂高频
考察点：位置编码与长度外推
大白话
位置编码告诉模型词在第几位。RoPE 旋转式编码效果好、外推长上下文强，所以成了主流。
详细答案
Transformer 本身没有时序概念，需要注入位置信息。常见方案：① 正弦/余弦绝对位置编码（Transformer 原版）；② 可学习位置编码（BERT）；③ RoPE 旋转位置编码；④ ALiBi 线性偏置。RoPE 是当前主流，因为它把位置信息编码成旋转角度作用于 Q/K，天然表达相对位置关系，且支持长度外推（训练 4K 可推理 8K/32K），与现有注意力实现兼容好。

为什么现在主流大模型都用 Decoder-only 结构？

🔥 🔥 字节/阿里高频
考察点：架构选型理解
大白话
Decoder-only 只管往下接话，天然适合聊天和写作。GPT 系列全是这路子。
详细答案
原因有三：① 生成任务天然是自回归的，Decoder-only 用单向因果注意力，正好匹配"预测下一个 Token"的训练目标，训练和推理目标一致；② 结构简单，只用一套参数，扩展性好，GPT 系列证明了其 Scaling 能力；③ 推理更快，因果掩码天然支持 KV Cache 缓存。Encoder-Decoder（如 T5）在翻译等序列转换任务有优势，但通用对话与生成场景 Decoder-only 更高效。
追问：BERT（Encoder-only）和 GPT（Decoder-only）训练目标有什么区别？

什么是 Embedding？它和 Token 是什么关系？

中频
考察点：表示学习基础
大白话
Token 是文字碎片，Embedding 是把每个碎片变成一串数字，模型才能算。
详细答案
Token 是文本切分后的最小单位（离散符号），Embedding 是把这个离散符号映射成稠密向量（如 4096 维）的表示，是模型能处理的数值形式。Embedding 矩阵本质是一张查找表：每个 Token ID 对应一个向量。好的 Embedding 让语义相近的词在向量空间中距离更近（"苹果"和"水果"相近）。训练过程中 Embedding 会不断更新，最终编码语义信息。
追问：词向量（Word2Vec）和大模型的 Embedding 有什么区别？

Temperature、Top-k、Top-p 分别如何影响生成结果？

🔥 🔥 大厂高频
考察点：解码策略
大白话
Temperature 越高越随机；Top-k/Top-p 限制候选词范围。调这些 = 调创意还是稳。
详细答案
三者都控制生成的随机性。Temperature：对 Softmax 前的 logits 做缩放，温度越高分布越平缓、输出越随机有创意；温度越低越接近贪心、输出越确定严谨。Top-k：只从概率最高的 k 个 Token 里采样，防止"烂尾"候选被选到。Top-p（核采样）：从累积概率超过 p 的最小集合里采样，比 Top-k 更动态。实际使用通常"低温度 + Top-p"组合：事实问答用低温度，创意写作用高温度。
追问：温度=0 时输出是确定的吗？如何避免生成重复内容？

什么是 Scaling Law？Chinchilla 最优配比是什么？

中高频
考察点：规模定律
大白话
Scaling Law：参数、数据、算力要配着涨。Chinchilla 说：别只堆参数，数据也要够。
详细答案
Scaling Law 描述模型损失随参数量、数据量、计算量按幂律下降的可预测规律，即"更大模型 + 更多高质量数据 + 更多算力"稳定带来能力提升，这也是大模型军备竞赛的理论依据。但无脑堆参数会撞上数据瓶颈和成本问题。Chinchilla（DeepMind）提出计算最优配比：在固定算力下，模型参数与训练 Token 数应约 1:20 的比例（如 70B 模型配 1.4T Token），而不是只放大模型。
追问：训练数据耗尽后，模型能力提升靠什么？

什么是 MoE（混合专家）？路由机制是如何工作的？

🔥 🔥 腾讯/阿里高频
考察点：稀疏激活架构
大白话
MoE = 很多专家，每次只叫几个干活。总参数大，但每次激活的少，省钱又聪明。
详细答案
MoE 把网络中的 FFN 层替换成多个"专家"（Expert），每个 Token 由路由网络（Gate）打分后只激活 Top-k 个专家处理。这样总参数量可以很大（如 Mixtral 8x7B 总量 47B），但每个 Token 实际只激活一小部分（约 13B），计算量不会随总参数量线性增长，实现"大容量、低计算"的稀疏激活。核心挑战是路由选得准不准、专家负载是否均衡，通常配合负载均衡损失训练，避免 Token 都挤到少数专家。
追问：MoE 在推理部署上有什么难点？（显存、通信）

Tokenizer 是什么？BPE、WordPiece、SentencePiece 有什么区别？

中高频
考察点：分词算法
大白话
Tokenizer 把句子切成模型认识的块。BPE/WordPiece/SentencePiece 是不同切法，思路差不多。
详细答案
Tokenizer 把原始文本切成 Token 并映射为词表 ID（编码），生成时再把 ID 反解成文本（解码），是模型的第一道和最后一道工序。BPE：不断合并语料中出现频率最高的字符对，直到达到目标词表大小；WordPiece：每次合并"能使语言模型概率提升最大"的片段；SentencePiece：不依赖空格分词，直接在原始文本上训练，对多语言和中文更友好。三者都是子词级切分，现在大模型普遍用 SentencePiece/BPE。
追问：中文为什么不按字切分？词表大小如何影响模型？

大模型训练一般分为哪几个阶段？

🔥 🔥 字节/腾讯高频
考察点：训练全流程
大白话
训练三阶段常见：预训练（大量读书）→ SFT（教听指令）→ RLHF/DPO（教说人话）。
详细答案
一般分四步：① 预训练（Pretraining）：在海量无标注语料上做"预测下一个 Token"，学习通用语言知识与世界常识；② 监督微调（SFT）：用高质量的指令-回答数据训练，让模型学会遵循指令、按人类习惯回答；③ 对齐训练（RLHF/DPO）：让输出更符合人类偏好与安全要求，拒绝有害内容；④ 部署优化：量化、蒸馏、推理加速等，让模型能低成本上线。不同团队侧重点不同，但大方向通用。
追问：预训练、SFT、RLHF 分别解决什么问题？

预训练数据为什么重要？数据清洗主要做什么？

中高频
考察点：数据工程
大白话
数据质量决定上限。清洗就是去垃圾、去重复、去有害内容，Garbage in garbage out。
详细答案
预训练数据决定了模型的知识边界、语言能力和底层分布，甚至比模型结构更影响上限。数据清洗主要做：去重（网页语料里镜像页、模板页极多）、去噪（乱码、广告、低信息密度文本）、去低质量、过滤非法与有害内容、统一格式，还要控制领域分布与语言分布。数据没清好，训练再多轮效果也上不去，后续微调很难完全补回来。

什么是 SFT？指令微调数据如何构建？

🔥 🔥 大厂高频
考察点：监督微调与数据构造
大白话
SFT = 用「问题-好答案」对教模型按指令回答。数据要像真实用户会怎么问。
详细答案
SFT（Supervised Fine-Tuning）是用高质量"指令-回答"配对数据对预训练模型做有监督微调，让模型学会按指令格式回答。数据构建流程：① 收集/生成真实业务场景的指令；② 人工撰写或模型辅助生成高质量回答；③ 清洗去重、保证难度与领域分布合理；④ 格式化为对话模板（如 ChatML）。数据质量 > 数量，通常几万条高质量指令即可有明显效果，关键要覆盖任务类型、难度梯度，避免单一模板导致模型"变傻"。

什么是 RLHF？三阶段流程和 PPO 原理是什么？

🔥 🔥 字节/腾讯高频
考察点：人类反馈强化学习
大白话
RLHF = 人打分 → 训练奖励模型 → 用 PPO 让模型讨好人类偏好。三阶段，贵但有效。
详细答案
RLHF 分三阶段：① SFT：先用指令数据微调出一个基础对话模型；② 训练奖励模型（RM）：让人类对同一问题的多个回答排序打分，训练一个打分模型模拟人类偏好；③ PPO 强化学习：用 RM 的分数作为奖励，通过 PPO 算法更新主模型，让模型输出越来越符合人类偏好。PPO 的核心是重要性采样 + 裁剪（clip）目标，防止策略更新过大导致训练不稳定，同时用 KL 惩罚约束新策略不偏离参考模型太远。
追问：奖励模型怎么训练？为什么 PPO 训练容易不稳定？

什么是 DPO？它和 RLHF/PPO 相比有什么优势？

🔥 🔥 阿里/腾讯高频
考察点：偏好对齐新方法
大白话

LoRA 的原理是什么？为什么能大幅降低微调显存？秩 r 怎么选？

🔥 🔥 阿里/美团高频（必考）
考察点：参数高效微调（必考）
大白话
LoRA = 只训旁边两个小矩阵，不动大模型本体。显存省很多，r 越大容量越大但越费。
详细答案
LoRA（Low-Rank Adaptation）的核心假设：模型微调时的权重更新量是低秩的。做法是冻结原模型权重，在旁边插入两个小矩阵 A（降维）和 B（升维），训练时只更新 A、B（如 7B 模型只训几百万参数），最终把 BA 加回原权重。因为可训练参数量骤降，优化器状态、梯度的显存开销大幅降低（可减少约 2/3 显存），且不改变原模型结构，可热插拔切换多个任务。秩 r 一般取 8、16、32、64：r 越大表达能力越强但显存越高，常见默认 8~16；与模型规模和任务复杂度正相关。

什么是 KV Cache？它如何加速推理？显存怎么算？

🔥 🔥 字节/阿里高频
考察点：推理加速核心
大白话
KV Cache = 把前面算过的键值存起来，接下一个字不用重算。快，但占显存。
详细答案
KV Cache 是把历史 Token 的 Key 和 Value 张量缓存下来，生成下一个 Token 时只需要计算新 Token 的 Q、K、V，并复用缓存的 K/V 做注意力，避免对已生成内容重复计算。没有 KV Cache，每次生成都要从头算全部历史，复杂度 O(n²)；有了它，单步注意力变成 O(n)。显存估算：KV Cache 大小 ≈ 2（K+V）× 层数 × 头数 × 每头维度 × 序列长度 × 2（字节/FP16），7B 模型 4K 上下文约需 1~2GB。所以 MQA/GQA/MLA 通过共享 KV 大幅省显存。

vLLM 的 PagedAttention 解决了什么问题？

Rerank 为什么能显著提升 RAG 效果？

考察点：排序优化
大白话

详细答案

什么是思维链（CoT）的进阶变体 Self-Consistency 和 ToT？

考察点：推理增强
大白话

iOS 端 LLM 推理的线程模型怎么设计？

🔥 🔥 iOS AI 岗高频
考察点：并发与性能
大白话
推理放后台线程/队列，别卡主线程。流式结果回主线程更新 UI。
详细答案
核心原则：LLM 推理是 CPU/GPU 密集型任务，绝不能放主线程（会卡 UI）。设计要点：① 推理放专用后台队列（串行，避免并发推理互相抢资源）；② 生成结果用回调/流式回主线程刷新 UI（Swift 里用 Task/@MainActor 或 DispatchQueue.main）；③ 推理引擎内部建议多线程（llama.cpp 支持多线程并行计算，线程数按核心数配）；④ 内存峰值控制：加载模型前检查可用内存，不足时降级；⑤ 取消机制：用户停止生成时中断推理并释放资源；⑥ 后台任务：生成中 App 退后台要暂停/降频，防止被系统杀掉。
