iOS 内存管理机制是什么？ARC 和 MRC 区别？🔥 高频

内存管理
大白话
ARC = 编译器自动帮你数引用，为 0 就释放；MRC 要手动 retain/release。
详细答案
ARC（Automatic Reference Counting）在编译期插入 retain/release/autorelease 代码，运行时根据 strong 引用计数决定何时 deinit。MRC 是 iOS 5 之前手动管理，现在新项目几乎全 ARC。Struct/Enum 是值类型不走 ARC，只有 Class 实例才计数。

strong / weak / unowned / assign 分别是什么？🔥 高频

内存管理
大白话
strong 默认强引用；weak 弱引用变 nil；unowned 弱引用不 Optional 但对象没了会崩；assign 只用于基本类型。
详细答案
strong：默认，+1 计数。weak：不增加计数，对象释放后自动置 nil，必须 Optional，delegate 常用。unowned：不增加计数，对象释放后访问会 crash，用于生命周期确定的场景（如闭包和 self 同生共死）。assign：OC 属性修饰符，用于 int/float 等，对象类型用 assign 对象释放后指针悬空（野指针），所以对象属性不用 assign。

assign 和 weak 的区别？（Shopee/滴滴高频）🔥 高频

内存管理
大白话
assign 释放后指针还在（野指针）；weak 释放后自动变 nil，安全。
详细答案
weak 是弱引用，被引用对象 dealloc 时 weak 指针自动置 nil。assign 只是简单赋值，对象释放后内存地址还在，成为 dangling pointer，再访问可能 crash 或读到垃圾数据。Swift 里对象引用默认 strong，OC 里 delegate 必须 weak 不能 assign。

什么是循环引用（Retain Cycle）？🔥 高频

内存管理
大白话
两个对象互相 strong 指着对方，ARC 永远减不到 0，内存泄漏。
详细答案
典型场景：① VC 强引用 closure，closure 捕获 self；② 父对象 strong 子对象，子对象 delegate 没设 weak 又 strong 父对象；③ Timer 的 target 是 self。解决：一方改 weak/unowned，或闭包 [weak self]。

闭包为什么容易造成循环引用？🔥 高频

内存管理
大白话
闭包默认 strong 捕获外部变量，包括 self。
详细答案
Closure 捕获列表默认 strong。若 closure 被 self 的属性持有，又捕获了 self，就形成环。解决：[weak self] 或 [unowned self]，配合 guard let self = self else { return }。

weak self 和 unowned self 怎么选？🔥 高频

内存管理
大白话
不确定对象是否还活着用 weak；确定闭包比 self 活得短用 unowned。
详细答案
weak：对象可能先释放，闭包后执行，self 变 nil，安全。unowned：假设 self 一定比闭包活得长，否则 crash。面试标准答法：不确定就用 weak。

@escaping 和非 escaping 闭包与内存的关系？🔥 高频

内存管理
大白话
escaping 闭包可能逃出函数被长期持有，容易循环引用；非 escaping 函数返回就销毁。
详细答案
非 escaping：闭包在函数内同步执行完即销毁，不会和 self 形成长期环。escaping：闭包被存储或异步调用，编译器要求显式写 self，提醒注意捕获。

autoreleasepool 原理和作用？🔥 高频

内存管理
大白话
临时对象先放池里，池 drain 时统一 release，省内存峰值。
详细答案
RunLoop 每次循环会创建和销毁 autoreleasepool。大循环（解析海量图片、循环创建临时对象）里用 @autoreleasepool { } 及时释放。主线程 RunLoop 自动管理；子线程需手动创建 pool 否则临时对象可能延迟释放。

autorelease 对象什么时候释放？

内存管理
大白话
当前 RunLoop 迭代结束，或所在 autoreleasepool drain 时。
详细答案
对象 send autorelease 后进入当前 pool，pool 销毁时 refcount-1。不在 pool 里的 autorelease 对象会泄漏到外层 pool。
