中级 01：推理原理——大模型到底怎么"运行"

中级模块

学习目标：彻底搞懂大模型收到你的问题后，内部发生了什么。

学习目标：彻底搞懂大模型收到你的问题后，内部发生了什么。
一句话总结全章：大模型推理 = 一个字一个字地"猜"下一个字，猜完拼回去，再猜下一个，循环往复。

拆成 4 步：

第 1 步：拆词（Tokenization）

电脑不认识完整的句子，它只认识"小块"。把句子拆成小块的动作叫分词（Tokenize），拆出来的小块叫 Token。

示例
"电池要不要换" → ["电池", "要不要", "换"] （3 个 token） "I love you" → ["I", " love", " you"] （3 个 token）

为什么不能一个字一个字算？
- 单个字信息太少："电"字单独出现，可能是电池、电脑、电话……
- 而且太碎，效率低。所以大模型一般按"常用词/词组"来拆。

相关名词：
- 词表（Vocabulary）：模型认识的所有 token 的清单。Qwen 的词表大约有 15 万个 token。
- 上下文窗口（Context Window）：模型一次最多能"记住"多少 token。常见 1024~128K。

示例（上下文窗口）
你和 AI 聊了 50 轮，总字数超过 2000 token，但窗口只有 1024。
结果：AI 只记得最近的 1024 个 token，老早聊的它全忘了。
所以工程上要主动"截断"：只保留最近几轮对话。

第 2 步：变成数字（Embedding 向量化）

电脑不认识"电池"，只认识数字。所以每个 token 都要变成一串数字（向量）。

示例
"电池" → [0.32, -0.87, 1.02, 0.45, ...] （假设共 1536 个数字） "电量" → [0.35, -0.82, 0.98, 0.44, ...] （和"电池"很像） "香蕉" → [-0.91, 0.12, -0.55, 0.87, ...] （和"电池"差很远）

关键规律：意思相近的词，它们的数字列表也相近。
数学上算一下"两个向量的距离"，就知道两个词意思近不近。
这一步让模型有了"词义"概念——这就是 Embedding（嵌入）。

相关名词：
- 向量（Vector）：一串数字。在 AI 里，万物皆可向量：词、句子、图片都能变成向量。
- 维度（Dimension）：一个向量里有多少个数字。维度越高，能表达的信息越丰富。
- 语义距离：两个向量差多远 = 两个词意思差多远。

第 3 步：注意力机制（Attention）——大模型的灵魂

这是 Transformer 架构的核心，也是大模型"聪明"的根本原因。

比喻：在图书馆找答案。

想象你进了一间堆满书的图书馆，要回答"电池寿命和什么有关"。
你不会一本本翻，而是快速扫一眼所有书架，然后死死盯住最相关的几本书猛看。
注意力机制就是让模型学会"该盯着谁看"。

具体到文字处理：

示例
处理句子"电池要不要换"时，每个 token 都会"关注"句子里其他所有 token，并给每个"关注对象"打个分（注意力权重）：

"电池" 对 "换" 的关注度：0.85 ← 关系密切（换的是电池） "电池" 对 "要不要" 的关注度：0.60 ← 有关系（在问电池的事） "电池" 对 "电池" 的关注度：0.40 ← 自己看自己 "要不要" 对 "换" 的关注度：0.75 ← 关系密切（要不要换？）

模型根据这些"关注度"，把相关的词的信息加权混合在一起，
从而知道"哦，这句话的核心是：用户在问'要不要换电池'"。

关键点：
- 注意力是动态的：同一句话在不同语境下，关注对象不同。比如"苹果很好吃"和"苹果发布了新手机"里，"苹果"关注的词完全不同。
- 这个"互相看"的过程会重复几十层（比如 Qwen 有 24~32 层），每层都在更高层面提炼关系。所以叫深层网络（Deep）。
- 注意力机制的学名：Self-Attention（自注意力）——句子里每个词看句子里其他所有词。
- 还有 Multi-Head Attention（多头注意力）：相当于"同时派好几个图书管理员去找答案"，每个管理员关注不同角度（一个管语法、一个管语义、一个管情感……），最后汇总。

为什么 GPU 快？ 因为"每个词看所有词"本质上是大量矩阵乘法，而 GPU 天生就是矩阵乘法加速器（见高级模块）。

第 4 步：预测下一个字（概率 + 采样）

经过几十层注意力计算后，模型对"下一个字是啥"有了结论——不是直接给答案，而是给所有候选字各自的概率。

示例
输入"电池要不要换"后，模型算出下一个字的概率分布：
"建议" → 45% "考虑" → 20% "去" → 8% "先" → 5% "睡觉" → 2% ...（词表里每个字/词都有个概率，加起来 = 100%）

然后不是每次选概率最高的（那样回答太死板），
而是按概率抽签：45% 概率抽中"建议"，但也有小概率抽到别的。

相关名词：
- Softmax：把一堆原始分数变成"加起来=100% 的概率"的数学操作。
- 采样（Sampling）：按概率"抽签"选下一个字的过程。
- Greedy Decoding（贪心解码）：永远选概率最高的字。结果稳定但死板、容易重复。
- Temperature（温度）：控制"抽签的随机程度"（见下）。

温度（Temperature）：随机程度的旋钮

温度是生成回答时最重要的"手感旋钮"。

示例
温度 = 0.1（很冷）→ 几乎每次选概率最高的字 → 回答稳定、准确、但死板 温度 = 0.7（适中）→ 偶尔选冷门字 → 回答自然、有变化 温度 = 1.5（很热）→ 经常乱选 → 回答有创意，但容易胡说八道

生活里的类比：温度低 = 每次都点同一个招牌菜（稳）；温度高 = 闭眼乱点（刺激但可能踩雷）。

流式输出（Streaming）：打字机效果

大模型生成是一字一字来的，如果要等整段生成完再显示，用户要干等十几秒。所以有了流式输出：生成一个字，立刻显示一个字，像打字机一样。

示例
你问完问题，屏幕上是这样的：
第 0.1 秒："建" 第 0.3 秒："建议" 第 0.6 秒："建议你" 第 1.0 秒："建议你先" ...最后完整出现："建议你先观察几天，如果持续掉电再考虑换电池。"

上下文窗口（Context Window）

模型一次能"看在眼里"的最长内容长度，单位是 token。

示例
- 窗口 1024 → 大约能记住 700~1000 个汉字
- 窗口 128K（如 GPT-4 Turbo）→ 能"读"完一整本 200 页的书

超出窗口的内容，模型根本看不见，不是"忘了"，是"没看到过"。

全章串一遍（终极示例）

你打字："电池要不要换？"
  → 第 1 步：拆成 ["电池","要不要","换","？"]（token 化）
  → 第 2 步：每个 token 变成一串数字（向量化）
  → 第 3 步：层层注意力扫描——"电池"和"换"关系最密切
  → 第 4 步：算出所有候选字的概率表
  → 按概率抽一个："建"
  → 拼回去，再算下一个："议"
  → 再算："你"
  → ……循环，屏幕上就一个字一个字蹦出完整回答

本质：大模型就是个超级复杂的"概率预测机"。它不是"懂"你，它是从参数里总结出的模式里，算出"人类听到这句话，最可能接着说什么"。
