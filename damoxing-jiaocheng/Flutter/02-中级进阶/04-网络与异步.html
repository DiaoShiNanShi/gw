04-网络与异步

大白话版 · 网络请求、JSON 解析与异步处理（小白向）
目标：学会用 dio 发起网络请求、用 json_serializable 解析 JSON、处理缓存与错误、做好加载态。

一、先讲"是什么"：网络请求到底是干什么的？

一句话版本：App 通过"网络请求"去服务器要数据（或提交数据），拿到后展示给用户。

打个比方：

你去餐厅（App）吃饭：
- 你点菜 = 发请求（告诉服务器我要什么）
- 后厨做菜 = 服务器处理
- 服务员端菜上来 = 服务器返回数据（JSON）
- 你吃到嘴里 = App 把数据显示到界面

你点完菜不会傻站着干等吧？——这就引出了异步：点完菜可以先玩手机，菜到了再放下手机开吃。

一个完整流程（大白话）

App 发请求（GET 天气接口）
    ↓  网络传输（异步，不等）
服务器返回 JSON：{"city":"北京","temp":28}
    ↓
App 把 JSON 解析成 Dart 对象
    ↓
界面显示"北京 28°C"（加载态结束）

关键概念先记住

名词 大白话 类比
API / 接口 服务器提供的"取数窗口" 餐厅的点菜窗口
HTTP 请求 你要数据的动作 点菜
响应（Response） 服务器给回的数据 上菜
JSON 数据的通用"快递箱格式" 统一规格的打包盒
异步（async/await） 不阻塞主流程地等待 点完菜先干别的
缓存 把数据先存一份本地 把菜拍照存手机，下次没网也能看

二、再讲"为什么"：为什么用 dio？为什么要封装？

2.1 为什么用 dio 而不是自带的 http？

Flutter 自带的 http 包简单但功能弱；dio 是社区最火的网络库，功能全、好用：

能力 http dio
基础 GET/POST ✅ ✅
超时设置 要手动 ✅ 一行搞定
拦截器（统一加 token） ❌ ✅
上传/下载进度 麻烦 ✅
取消请求 麻烦 ✅
FormData 表单 麻烦 ✅

大白话：dio 是"增强版 http"，自带拦截器、超时、进度等生产级功能，实战首选。

2.2 为什么要把网络请求"封装"？

大白话： 把"发请求 + 解析 + 错误处理"这套重复代码写成一个工具类，所有页面共用。好处：

  1. 一处改，处处生效：比如服务器地址变了、要统一加 token，只改封装文件。
  2. 代码不重复：不用每个页面都写一套 try-catch。
  3. 规范统一：所有请求都走同一个"大门"，好排查问题。

3.2 深入 Future / async / await（吃透异步三兄弟）

先复习再深入。一句话：Future 是"未来的值"，async 标记"这个函数有异步操作"，await 是"等它"。

// 基础：模拟网络延迟 2 秒返回数据
Future<String> fetchData() async {
  await Future.delayed(const Duration(seconds: 2));
  return '服务器数据';
}

// 进阶 1：链式调用（.then 等价于 await，但 await 更易读）
Future<void> useThen() {
  return fetchData().then((data) {
    print('拿到：$data');
  });
}

// 进阶 2：多个请求并行（Future.wait：同时发，全部回来才继续）
Future<void> fetchAll() async {
  final results = await Future.wait([
    fetchData(),
    fetchData(),
  ]);
  print(results);  // [服务器数据, 服务器数据]
}

// 进阶 3：错误处理（try-catch 捕获异常，绝不崩）
Future<void> safeFetch() async {
  try {
    final data = await fetchData();
    print('成功：$data');
  } catch (e) {
    print('失败了：$e');  // 网络错误、超时都会进这里
  } finally {
    print('不管成功失败，这里都会执行（比如关 loading）');
  }
}

错误处理三种状态（大白话）：
- 加载中（loading）：显示转圈
- 成功（success）：显示数据
- 失败（error）：显示"重试"按钮

3.3 用 dio 发请求（核心代码）

// 第一步：创建 dio 实例（全局共用一份）
import 'package:dio/dio.dart';

class ApiClient {
  // 单例：整个 App 共用一个 dio
  static final ApiClient instance = ApiClient._();
  ApiClient._();

  // baseUrl：所有请求的前缀（服务器地址）
  final Dio _dio = Dio(BaseOptions(
    baseUrl: 'https://api.example.com',
    connectTimeout: const Duration(seconds: 10),  // 连接超时
    receiveTimeout: const Duration(seconds: 10),  // 接收超时
  ));

  // 拦截器：每次请求自动加 token（相当于 Alamofire 的 interceptor）
  void init() {
    _dio.interceptors.add(InterceptorsWrapper(
      onRequest: (options, handler) {
        options.headers['Authorization'] = 'Bearer 你的token';
        handler.next(options);  // 放行
      },
      onError: (e, handler) {
        // 统一错误处理：超时、断网、500 都走到这
        handler.next(e);
      },
    ));
  }

  // 第二步：封装一个 GET 请求方法
  Future<dynamic> get(String path, {Map<String, dynamic>? query}) async {
    final response = await _dio.get(path, queryParameters: query);
    return response.data;  // 返回解析后的数据（一般是 Map/List）
  }
}

使用封装（在页面里）：

Future<void> loadWeather() async {
  try {
    // 请求数据
    final data = await ApiClient.instance.get('/weather', query: {'city': '北京'});
    // data 是一个 Map：{ "city": "北京", "temp": 28 }
    debugPrint('城市：${data['city']}，温度：${data['temp']}');
  } catch (e) {
    debugPrint('请求失败：$e');
  }
}

3.4 JSON 解析（用 json_serializable 自动生成代码）

JSON 是字符串，Dart 对象是"模型类"。解析 = 把 JSON 字符串变成 Dart 对象。

手动解析（小数据够用）：

// JSON 长这样：{"city":"北京","temp":28}
class Weather {
  final String city;
  final int temp;

  Weather({required this.city, required this.temp});

  // 手动从 Map 构造
  factory Weather.fromJson(Map<String, dynamic> json) {
    return Weather(
      city: json['city'] as String,
      temp: json['temp'] as int,
    );
  }
}

// 使用
final data = await ApiClient.instance.get('/weather', query: {'city': '北京'});
final weather = Weather.fromJson(data);
print('${weather.city} ${weather.temp}°C');

自动生成（项目大了用 json_serializable）：

// 第一步：定义模型类，加注解
import 'package:json_annotation/json_annotation.dart';

part 'weather.g.dart';  // 生成的代码文件（build_runner 自动生成）

@JsonSerializable()  // 告诉工具"帮我生成解析代码"
class Weather {
  final String city;
  final int temp;
  Weather({required this.city, required this.temp});

  // 这两个方法由 build_runner 自动生成，不用手写
  factory Weather.fromJson(Map<String, dynamic> json) => _$WeatherFromJson(json);
  Map<String, dynamic> toJson() => _$WeatherToJson(this);
}

# 第二步：在项目目录运行命令，自动生成 weather.g.dart
flutter pub run build_runner build

大白话：你只写模型类（字段 + 注解），build_runner 帮你自动生成"解析代码"，字段多了也不用手写，省时且不易出错。
对 iOS 工程师：≈ Codable 的 Codable 协议 + 自动合成，但 Flutter 需要额外跑一次代码生成命令。

3.5 缓存与加载态（实战落地）

缓存（用 shared_preferences 存最近一次数据）：

import 'package:shared_preferences/shared_preferences.dart';

// 存：请求成功后把原始 JSON 字符串存本地
Future<void> saveCache(String key, String jsonString) async {
  final prefs = await SharedPreferences.getInstance();
  await prefs.setString(key, jsonString);
}

// 取：没网或请求失败时，读上次的缓存兜底
Future<String?> readCache(String key) async {
  final prefs = await SharedPreferences.getInstance();
  return prefs.getString(key);
}

完整加载态（加载中 → 成功 / 失败重试）：

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: WeatherPage()));

class WeatherPage extends StatefulWidget {
  const WeatherPage({super.key});
  @override
  State<WeatherPage> createState() => _WeatherPageState();
}

class _WeatherPageState extends State<WeatherPage> {
  bool _loading = true;      // 是否加载中
  String? _error;            // 错误信息（null 表示没错误）
  String _weather = '';      // 成功后的数据

  @override
  void initState() {
    super.initState();
    _load();  // 页面一进来就开始加载
  }

  // 加载数据
  Future<void> _load() async {
    setState(() {
      _loading = true;
      _error = null;
    });
    try {
      // 模拟请求
      await Future.delayed(const Duration(seconds: 2));
      final data = '北京 28°C';
      setState(() => _weather = data);  // 成功：更新数据
    } catch (e) {
      setState(() => _error = '加载失败，请重试');  // 失败：记下错误
    } finally {
      setState(() => _loading = false);  // 无论如何：关闭加载态
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('天气')),
      body: Center(
        child: _buildContent(),  // 根据状态渲染不同内容
      ),
    );
  }

  // 根据状态决定显示什么（三态：加载 / 失败 / 成功）
  Widget _buildContent() {
    if (_loading) {
      return const CircularProgressIndicator();  // 转圈圈
    }
    if (_error != null) {
      return Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Text(_error!),
          const SizedBox(height: 12),
          ElevatedButton(onPressed: _load, child: const Text('重试')),  // 重试按钮
        ],
      );
    }
    return Text(_weather, style: const TextStyle(fontSize: 24));  // 成功展示数据
  }
}

给 iOS 工程师的真心话：
- 异步写法和你熟悉的一模一样：async 函数 + await 调用 + try-catch，零学习成本。
- Codable 对应 Flutter 的 json_serializable，只是 Flutter 需要跑一次 build_runner 生成代码，多一步但原理相同。
- dio 拦截器就是 Alamofire 的 RequestInterceptor，用来统一加 token、处理 401 跳登录，思路完全一致。
- 加载态三态（loading / error / success）在任何平台都是通用套路，你直接用。

五、小节小结

  1. 网络流程：发请求 → 异步等待 → 收到 JSON → 解析 → 展示。
  2. Future / async / await 是异步三兄弟；Future.wait 并发、try-catch 容错。
  3. 网络库选 dio：自带拦截器、超时、进度，实战首选；要封装成单例工具类。
  4. JSON 解析：小数据手写 fromJson，大数据用 json_serializable + build_runner 自动生成。
  5. 缓存：shared_preferences 存最近数据，断网/失败时兜底。
  6. 加载态：loading（转圈）/ success（数据）/ error（重试）三态切换，是生产级页面的标配。

六、本节动手练习（含答案提示）

练习 1：判断异步

为什么网络请求必须用 async/await，而不能直接同步等待？

✅ 答案提示：网络请求耗时不定（可能几秒）。如果同步等待，界面会卡死（阻塞主线程），用户无法操作。异步让界面保持流畅，数据到了再刷新。

练习 2：补全错误处理

在 try { await request(); } 后面补上捕获异常并打印的代码。

✅ 答案提示：catch (e) { print('请求失败：$e'); }（还可加 finally { ... } 处理收尾）。

练习 3：理解 Future.wait

Future.wait([f1, f2]) 和 await f1; await f2; 有什么区别？

✅ 答案提示：Future.wait 是并行（两个同时跑，都完成才继续），更快；await f1; await f2; 是串行（先等 f1 完成再等 f2），更慢。互不依赖的请求用 Future.wait。

练习 4：JSON 解析

服务器返回 {"name":"iPhone 15","price":5999}，请写出对应的 Dart 模型类的 fromJson 工厂方法。

✅ 答案提示：
dart factory Product.fromJson(Map<String, dynamic> json) { return Product( name: json['name'] as String, price: json['price'] as int, ); }

练习 5：设计三态

一个商品详情页需要哪些"状态"？分别对应什么界面？

✅ 答案提示：三态——加载中（转圈/骨架屏）、成功（展示商品信息）、失败（错误提示 + 重试按钮）；可选"缓存态"（先用缓存数据，再静默刷新）。
