03-路由导航

大白话版 · 页面跳转与传参（小白向）
目标：学会用 Navigator 跳转页面、命名路由、页面间传值（值/对象/回传结果）、并了解路由拦截与深链。

一、先讲"是什么"：路由（Route）到底是什么？

一句话版本：路由 = "页面跳转的路线"。你告诉 App"我要去哪个页面"，App 负责把你送过去（也能把你送回来）。

打个比方：

你逛一个商场（App）：
- 每个店铺（页面）都有自己的"门牌号"（路由地址）
- 你想从 1 楼（首页）去 3 楼咖啡店（详情页）——这就是一次路由跳转
- 喝完咖啡你坐电梯回 1 楼——这就是返回
- 商场里的"导航台"就是 Navigator（导航器），它知道所有路线，还帮你"记着"你来时的路（维护一个"页面栈"）

页面栈（Navigator 的"电梯记录"）

Navigator 用"栈"（Stack）管理页面：每跳进一个新页面就压栈（入栈），每返回一次就出栈。

栈底                   栈顶
[首页] → [详情页] → [支付页]
   ↑ 压栈（push）          ↑ 出栈（pop）回到详情页
  • push：把新页面压到栈顶（跳转）
  • pop：把栈顶页面弹出去（返回）

对 iOS 工程师：这就是 UINavigationController 的 pushViewController / popViewController，一模一样的栈模型。

二、再讲"为什么"：为什么要学路由？

  1. 任何 App 都要多页面：跳转是基本功，面试必问。
  2. 页面要传数据：从列表点进详情，得把"点了哪一条"告诉详情页；详情页操作完，可能要"带结果回去"（比如选完地址返回首页）。
  3. 工程化需要命名路由：项目大了之后，用"名字"跳转比直接 new 一个页面更清晰、更好维护。
  4. 高级能力：路由拦截（比如"没登录就跳登录页"）、深链（外部链接直接打开 App 某个页面）都是真实业务需求。

三、怎么用：四种跳转姿势逐个击破

3.1 姿势一：普通跳转（直接 new 目标页面）

最直接的方式，适合页面少的小项目：

import 'package:flutter/material.dart';

// 首页
class HomePage extends StatelessWidget {
  const HomePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('首页')),
      body: Center(
        child: ElevatedButton(
          // Navigator.push：跳转到新页面
          // MaterialPageRoute：给新页面包一个"带过渡动画的路线"
          onPressed: () {
            Navigator.push(
              context,
              MaterialPageRoute(builder: (context) => const DetailPage()),
            );
          },
          child: const Text('去详情页'),
        ),
      ),
    );
  }
}

// 详情页
class DetailPage extends StatelessWidget {
  const DetailPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('详情页')),
      body: Center(
        child: ElevatedButton(
          // Navigator.pop：返回上一页
          onPressed: () => Navigator.pop(context),
          child: const Text('返回'),
        ),
      ),
    );
  }
}

void main() => runApp(const MaterialApp(home: HomePage()));

3.2 姿势二：页面传值（跳转时带数据过去）

用 构造函数参数 传值，最简单直接：

// 详情页：接收一个 id 和名字
class DetailPage extends StatelessWidget {
  final int id;
  final String name;
  const DetailPage({super.key, required this.id, required this.name});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('详情：$name')),
      body: Center(child: Text('拿到了 id=$id, name=$name')),
    );
  }
}

// 首页跳转时把数据传进去
Navigator.push(
  context,
  MaterialPageRoute(
    builder: (context) => DetailPage(id: 1001, name: '苹果'),  // 传值！
  ),
);

传递复杂对象也一样：只要目标页面构造函数接收那个对象就行：

// 假设有个商品类
class Product {
  final int id;
  final String title;
  final double price;
  Product({required this.id, required this.title, required this.price});
}

// 详情页直接接收 Product 对象
class ProductPage extends StatelessWidget {
  final Product product;
  const ProductPage({super.key, required this.product});
  // ... 界面里直接用 product.title / product.price
}

// 跳转
Navigator.push(
  context,
  MaterialPageRoute(builder: (context) => ProductPage(product: myProduct)),
);

3.3 姿势三：结果回传（从下一页带数据回来）

比如"选择城市"页面选完，要把选中的城市传回首页。用 push 的返回值（Future）实现：

// 首页：发起跳转，并 await 结果
Future<void> _selectCity(BuildContext context) async {
  // push 返回的是一个 Future，结果就是下一页 pop 时传回来的值
  final result = await Navigator.push<String>(
    context,
    MaterialPageRoute(builder: (context) => const CityPickerPage()),
  );

  // result 为空说明用户没选就返回了（返回 null）
  if (result != null) {
    // 用结果做点什么（这里示例是打印）
    debugPrint('用户选择了城市：$result');
  }
}

// 选择城市页：选中后把值传回去
class CityPickerPage extends StatelessWidget {
  const CityPickerPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('选择城市')),
      body: ListView(
        children: ['北京', '上海', '广州', '深圳'].map((city) {
          return ListTile(
            title: Text(city),
            // 点击城市：pop 的时候把值带回去！
            onTap: () => Navigator.pop(context, city),
          );
        }).toList(),
      ),
    );
  }
}

大白话理解回传：

await Navigator.push(...) = "你去下一页办事，办完把结果带回来我再继续"。
下一页 Navigator.pop(context, 值) = "我办完了，把结果交给你"。

3.4 姿势四：命名路由（给页面起个"门牌号"）

项目大了，把路由集中注册，用"名字"跳转，好维护：

void main() {
  runApp(
    MaterialApp(
      // 初始页面：'/'
      initialRoute: '/',
      // 路由表：门牌号 → 页面
      routes: {
        '/': (context) => const HomePage(),
        '/detail': (context) => const DetailPage(),
        '/settings': (context) => const SettingsPage(),
      },
    ),
  );
}

// 用名字跳转
Navigator.pushNamed(context, '/detail');

// 用名字跳转 + 传参（通过 arguments）
Navigator.pushNamed(context, '/detail', arguments: Product(id: 1, title: '香蕉', price: 5.0));

// 目标页面里接收参数
class DetailPage extends StatelessWidget {
  const DetailPage({super.key});
  @override
  Widget build(BuildContext context) {
    // 取出 arguments 参数
    final product = ModalRoute.of(context)!.settings.arguments as Product;
    return Scaffold(body: Center(child: Text('收到商品：${product.title}')));
  }
}

对 iOS 工程师：命名路由 ≈ 注册表形式的"页面工厂"，比直接用类跳转更像 storyboard 里的 segue identifier。

四、路由拦截与深链（进阶了解）

4.1 路由拦截（onGenerateRoute）

大白话： 在每次跳转前，先经过一个"保安"检查。保安可以：放行、拦截、重定向到别的页面。

典型场景：未登录用户访问"我的订单"，强制跳转到登录页。

MaterialApp(
  onGenerateRoute: (settings) {
    // settings.name 就是要去的路由名字
    if (settings.name == '/orders') {
      // 假设这里判断未登录
      bool isLoggedIn = false;
      if (!isLoggedIn) {
        // 拦截！改道去登录页
        return MaterialPageRoute(builder: (context) => const LoginPage());
      }
    }
    // 其余正常放行
    return MaterialPageRoute(builder: (context) => const HomePage());
  },
)

4.2 深链（Deep Link）

大白话： 用户点一个外部链接（比如短信里的 myapp://product/123），直接打开 App 并跳到对应页面。

  • 原理：在 iOS 端配置 URL Scheme（Info.plist）或 Universal Links，Android 配置 intent-filter，App 收到链接后解析并跳转。
  • Flutter 里常用包：app_links / uni_links。
  • 了解即可，实战时按官方文档配置。

五、iOS 开发者视角（老司机对照表）

iOS 原生 Flutter 大白话
UINavigationController Navigator 页面导航器（栈管理）
pushViewController Navigator.push 压栈跳转
popViewController Navigator.pop 出栈返回
构造函数传值 / 属性传值 构造函数参数传值 跳转传参
闭包回调 / delegate 回传 await push 返回值 + pop(值) 结果回传
storyboard segue 命名路由（routes） 注册式跳转
navigationController 代理拦截 onGenerateRoute 路由拦截
URL Scheme / Universal Link 深链（app_links 包） 外部链接打开页面
navigationController?.viewControllers Navigator 的栈 页面栈

给 iOS 工程师的真心话：
- 栈模型、push/pop 你完全不用重新学，就是把 navigationController 换成了 Navigator。
- 最不一样的是"结果回传"：iOS 用 delegate/闭包，Flutter 用 await push 拿返回值，其实更简单，像 Swift Concurrency 一样顺手。
- 命名路由 + arguments 有点像 performSegue(withIdentifier:) 传 sender，概念互通。

六、小节小结

  1. 路由 = 页面跳转路线，Navigator 用"栈"管理（push 入栈 / pop 出栈）。
  2. 三种传值：构造函数传参（带数据过去）、pop(值) + await push（带结果回来）、arguments（命名路由传参）。
  3. 命名路由：集中注册 + 名字跳转，适合大项目。
  4. 路由拦截：onGenerateRoute 做"保安"，可实现登录校验、重定向。
  5. 深链：外部链接打开指定页面，实战按需配置。

七、本节动手练习（含答案提示）

练习 1：判断跳转方式

从首页跳转到"选择地址页"，选完地址要把地址带回首页。应该用哪种方式？

✅ 答案提示：用 await Navigator.push<String>(...) 跳转，地址页 Navigator.pop(context, 地址字符串) 回传，首页 await 拿到结果。

练习 2：补全代码

下面代码跳转时把 name: '张三' 传给详情页，补全缺失部分：
dart Navigator.push( context, MaterialPageRoute(builder: (context) => ____), );

✅ 答案提示：DetailPage(name: '张三')（前提 DetailPage 构造函数有 required this.name）。

练习 3：理解 pop 返回值

Navigator.pop(context) 和 Navigator.pop(context, '北京') 有什么区别？

✅ 答案提示：前者只返回上一页、不带数据；后者返回上一页的同时把 '北京' 作为结果传回去，上一页的 await push 能拿到这个值。

练习 4：实现拦截

需求：未登录用户点击"我的订单"时，自动跳转到登录页。用什么实现？

✅ 答案提示：用 MaterialApp.onGenerateRoute 做路由拦截：当 settings.name == '/orders' 且未登录时，返回 LoginPage 的 route 而非订单页。

练习 5：概念连线

连线：Navigator ↔ ？　push ↔ ？　pop ↔ ？　URL Scheme ↔ ？

✅ 答案提示：Navigator ↔ UINavigationController；push ↔ pushViewController；pop ↔ popViewController；URL Scheme ↔ 深链。
