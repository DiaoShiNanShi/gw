02-性能优化

大白话版 · 性能优化实战（小白向）
目标：学会列表优化、const 优化、重绘分析、启动速度、包体积和内存泄漏排查。

一、先讲"是什么"：性能优化到底在优化什么？

一句话版本：性能优化 = 让 App 更流畅（不卡顿）、启动更快、包更小、不崩不泄漏。

打个比方：

你的 App 像一家餐厅：
- 流畅度：高峰期上菜快不快（不卡顿）
- 启动速度：顾客进门到坐下点菜多快（启动时间）
- 包体积：厨房占多大地方（安装包大小）
- 内存泄漏：有没有"用过的碗碟不洗、越堆越多"（内存越占越多最后崩溃）

性能优化就是把这四个环节都调理顺。

卡顿的根本原因（必懂）

屏幕每秒刷新 60 次（60fps），每帧只有约 16.7 毫秒（1000/60）来完成任务。
如果一帧的活儿超过 16.7ms，就会"掉帧"——用户感觉就是卡顿。

一帧的时间线（16.7ms）：
[   Dart 代码执行   ][   渲染    ][   绘制上屏   ]
        必须赶在 16.7ms 内全部完成！

大白话： 一帧就像一次"限时任务"，超时就是卡顿。优化的核心 = 让每帧的活变少。

二、再讲"为什么"：常见的性能杀手有哪些？

性能杀手 大白话 后果
列表一次性建太多 一口气把 10000 个 cell 全造出来 卡顿、内存暴涨
没写 const 每次重建都重新"画"一遍不变的零件 浪费 CPU
重绘范围太大 只改一个小图标，整页全部重画 掉帧
主线程干重活 在主线程解析大 JSON、读大文件 界面卡死
内存泄漏 页面关了，对象还不释放 内存越用越多、闪退
包体积大 塞了很多没用的大资源/代码 下载慢、审核烦

三、怎么用：六大优化逐个击破

3.1 优化一：列表性能（ListView.builder + 懒加载 + 缓存）

问题： 用 ListView(children: [...]) 会一次性创建所有条目。
解决： 用 ListView.builder 按需创建 + itemExtent 固定高度 + addAutomaticKeepAlives 缓存。

// 好的写法：builder 按需生成，滚动到哪才建哪
ListView.builder(
  itemCount: 10000,
  itemExtent: 72,                 // 固定每行高度：让滚动计算更快
  cacheExtent: 200,               // 预加载范围：提前渲染可视区外一点点
  itemBuilder: (context, index) {
    return ListTile(
      leading: const CircleAvatar(child: Icon(Icons.person)),
      title: Text('用户 $index'),
    );
  },
)

ListTile 内部的 keepAlive（大白话）：
- addAutomaticKeepAlives: true（默认开启）：滚出屏幕的条目先"缓存"不销毁，滚回来不用重建。
- 好处：来回滚不卡；代价：占一点内存。列表项很重时改为 false 省内存。

列表优化口诀：
1. 大量数据 → 一定用 ListView.builder / GridView.builder。
2. 行高固定 → 加 itemExtent（省去测量高度）。
3. 每行内容不变 → 能 const 就 const。
4. 图片 → 用 cached_network_image 缓存，不重复下载。

3.2 优化二：const 优化（免费的午餐）

大白话： const 告诉 Flutter："这个 Widget 永远不会变"。重建时 Flutter 直接复用同一个实例，不用重新创建。

// 坏的写法：每次 build 都新建，浪费
Text('标题', style: TextStyle(fontSize: 20))

// 好的写法：const 让 Flutter 复用
const Text('标题', style: TextStyle(fontSize: 20))

怎么找漏网之鱼： 在 Android Studio / VS Code 里跑 flutter analyze，会提示"Use const"。看到提示就加。

对 iOS 工程师：const ≈ Swift 里"不可变 + 缓存复用"的组合拳，Flutter 编译器还能帮你自动复用，性能免费提升。

3.3 优化三：重绘分析（RepaintBoundary）

问题： 默认情况下，一个组件重绘，可能带动整个页面重绘。
解决： 用 RepaintBoundary 把"容易变的部分"隔离起来——它变了只重绘它自己，不影响别人。

// 场景：一个列表里有个"会动的加载动画"，不希望它带动整行/整页重绘
ListView.builder(
  itemBuilder: (context, index) {
    return RepaintBoundary(   // 隔离层：里面怎么变都不影响外面
      child: ListTile(
        title: Text('第 $index 条'),
        trailing: index % 10 == 0
            ? const SizedBox(
                width: 20, height: 20,
                child: CircularProgressIndicator(strokeWidth: 2),  // 会转的圈
              )
            : const Icon(Icons.check),
      ),
    );
  },
)

怎么定位重绘问题（DevTools）：
1. 运行 App 时开启"Debug 模式下的性能叠加层"：
- Android Studio：View → Tool Windows → Flutter Inspector → Enable Repaint Rainbow
- 或运行代码 debugPaintLayerBordersEnabled = true 看边界
2. 开启后，频繁重绘的区域会闪烁，闪烁的地方就该加 RepaintBoundary。

对 iOS 工程师：RepaintBoundary ≈ CALayer 的 shouldRasterize / 独立 layer，都是"隔离重绘区域"。

3.4 优化四：启动速度

启动慢的原因（大白话）： 启动时要执行很多代码——初始化 SDK、读配置、渲染首页。

优化手段：

手段 做法 大白话
首帧前别干重活 main() 里别做大量初始化 先上菜，再慢慢加调料
懒加载 非首屏模块按需 import / 延迟初始化 用到再加载
减少首屏 Widget 复杂度 首页别堆大量图片/动画 第一屏简单点
用 runApp 前预加载主题/字体 避免首帧后闪一下 先摆好桌布再上菜
发布用 flutter build 的 release 模式 开启 AOT 编译、Tree Shaking 去掉没用代码，跑更快

度量启动时间：

# 用 flutter run --profile 模式观察（release/profile 才接近真实）
flutter run --profile
# 或看 DevTools 的 Timeline 里的"首帧时间"

3.5 优化五：包体积

包体积大的原因： 代码里塞了没用的库、大图片、多平台资源。

优化手段（大白话版）：

手段 做法
Tree Shaking（默认开启） 发布时自动删掉没用的 Dart 代码
按需引入包 别为了一个功能装一个大库（比如能用 cached_network_image 就别装整个 image 全家桶）
压缩图片资源 图片用 WebP/压缩格式，别直接塞原图
清理无用资源 用 flutter clean + 检查 assets
拆分平台包 只打包用到的平台（不用的平台资源删掉）
用 flutter build appbundle（Android） 按设备架构分发，用户只下载需要的部分

查看包大小：

flutter build ios --release   # 构建后查看 .app 大小
ls -lh build/ios/iphoneos/*.app   # 看产物大小

3.6 优化六：内存泄漏排查（DevTools）

内存泄漏（大白话）： 页面关了，但它的对象还被别的东西"拽着"不释放，越积越多，最后内存爆掉闪退。

Flutter 最常见的泄漏原因：
1. 订阅/监听没取消（addListener 后没 removeListener）
2. AnimationController 没 dispose()
3. 全局/单例持有页面对象不放
4. 定时器（Timer）没取消

正确写法（防泄漏模板）：

class MyPage extends StatefulWidget {
  const MyPage({super.key});
  @override
  State<MyPage> createState() => _MyPageState();
}

class _MyPageState extends State<MyPage> {
  late final AnimationController _controller = AnimationController(
    vsync: this,
    duration: const Duration(seconds: 1),
  );
  Timer? _timer;  // 定时器

  @override
  void initState() {
    super.initState();
    // 启动定时器
    _timer = Timer.periodic(const Duration(seconds: 1), (_) {});
  }

  @override
  void dispose() {
    _controller.dispose();  // 1. 释放动画控制器
    _timer?.cancel();       // 2. 取消定时器
    super.dispose();
  }
}

用 DevTools 排查泄漏：
1. 运行 App，打开 DevTools（flutter run 后按 Shift + P 或 IDE 里点 DevTools）。
2. 切到 Memory 面板，反复进入/退出某个页面，观察内存曲线：
- 曲线"进页面涨、退出跌回原位" = 正常。
- 曲线"只涨不跌" = 有泄漏！
3. 用 Allocation Profile 看哪些对象堆积，找到泄漏源头。

DevTools 各面板速查（大白话）：

面板 用途 什么时候用
Performance 看帧耗时、定位卡顿 掉帧卡顿时
Memory 看内存曲线、找泄漏 内存只涨不跌时
Inspector 看 Widget 树、查 Repaint 边界 布局/重绘分析
Network 看网络请求耗时 接口慢时

四、iOS 开发者视角（老司机对照表）

iOS 原生 Flutter 大白话
UITableView 懒加载 ListView.builder 按需创建 cell
cell 复用（dequeueReusableCell） builder + keepAlive cell 缓存复用

给 iOS 工程师的真心话：
- ListView.builder + itemExtent 就是 UITableView 的"注册 cell + 固定行高 + dequeue 复用"，你熟得很。
- DevTools 就是 Flutter 版的 Instruments，Memory 面板看曲线找泄漏的思路和 Leaks 一样。
- 最关键的差异：Flutter 是"声明式重建"，所以 const 和 RepaintBoundary 是你需要新学的两个优化点，iOS 里没有完全对应的概念（CALayer 隔离略接近）。

五、小节小结

  1. 卡顿 = 一帧超时（>16.7ms）；优化核心 = 让每帧活变少。
  2. 列表性能：用 ListView.builder 按需创建 + itemExtent 固定行高 + keepAlive 缓存。
  3. const 优化：能加就加，Flutter 自动复用，零成本提速。
  4. RepaintBoundary：隔离重绘区域，小部件变不影响大页面。
  5. 启动速度：首帧前少干活、懒加载、release 模式构建。
  6. 包体积：Tree Shaking、按需引包、压缩图片、拆分平台资源。
  7. 内存泄漏：dispose() 释放控制器/定时器/监听；用 DevTools Memory 面板看曲线定位。

六、本节动手练习（含答案提示）

练习 1：判断卡顿原因

一个列表有 5000 条数据，用 ListView(children: List.generate(5000, ...)) 后非常卡。为什么？怎么改？

✅ 答案提示：一次性创建 5000 个 Widget，重建成本高。改成 ListView.builder（按需创建）+ itemExtent 固定行高，滚动到哪建哪。

练习 2：const 判断

下面的代码哪些能加 const？Text('你好')、Text(name)、Icon(Icons.star)、Image.network(url)

✅ 答案提示：Text('你好') 和 Icon(Icons.star) 可以加 const（内容编译期确定）；Text(name) 和 Image.network(url) 不能（依赖运行时变量）。

练习 3：RepaintBoundary 场景

页面里有一个一直转圈的加载动画，其余内容基本不变。为什么建议给动画加 RepaintBoundary？

✅ 答案提示：不加的话，动画每帧重绘可能带动整个页面重绘，浪费性能；加上后动画只在 RepaintBoundary 内部重绘，不影响外部。

练习 4：防泄漏

一个 StatefulWidget 里有 AnimationController 和 Timer，在哪个方法里清理？分别怎么清理？

✅ 答案提示：在 dispose() 里：_controller.dispose() 释放动画控制器、_timer?.cancel() 取消定时器。

练习 5：选工具

App 出现"内存只涨不跌、最后闪退"，用 DevTools 的哪个面板排查？重点看什么？

✅ 答案提示：用 Memory 面板。反复进出页面看内存曲线是否回落；用 Allocation Profile 看哪些对象持续堆积，定位泄漏源头。
