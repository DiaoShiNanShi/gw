03-环境搭建与第一个 App

大白话版 · Mac 上从零跑起 Flutter（小白向）
目标：装好 Flutter SDK、配好环境、创建项目、在模拟器上看到 Hello World。

一、先讲"是什么"：环境搭建到底在搭什么？

一句话版本：环境搭建 = 给 Flutter 装上"工具包"并告诉电脑"工具在哪"，让电脑能编译和运行 Flutter 代码。

打个比方：

你想开一家奶茶店。光有配方（代码）不够，你还得有：
- 厨房设备（Flutter SDK）——做奶茶的整套工具
- 水电燃气（Xcode / Android Studio）——让设备运转起来的基础设施
- 店铺地址（PATH 配置）——让系统知道"厨房设备"放在哪，随时能找到

本篇就是把"厨房"装修好，然后做第一杯奶茶（Hello World）。

我们最终要装什么（清单）

组件 作用 大白话
Flutter SDK Flutter 本体 做奶茶的"整套厨具"
Xcode（含 Command Line Tools） 编译 iOS App + 启动 iOS 模拟器 iPhone 的"水电"
Android Studio（可选） 编译 Android App + 安卓模拟器 安卓手机的"水电"
Chrome（可选） 跑 Flutter Web 网页版试喝窗口
VS Code 或 Android Studio 写代码的编辑器 你的"操作台"

如果你只想在 iPhone 模拟器上跑，Xcode 是必须的，Android Studio 可以先不装（后面做安卓再补）。

二、再讲"为什么"：为什么要这么装？

  • Flutter SDK 是核心：没有它，你写的 Dart 代码没人帮你翻译成 App。
  • Xcode 是 iOS 的"编译车间"：Flutter 在 iOS 上最终要借用 Xcode 的工具链把代码打包成 App（就像 Swift 代码需要 Xcode 编译一样）。
  • PATH 配置是为了"随处可用"：配好 PATH 后，你在终端任意目录敲 flutter 命令，系统都能找到它。不配的话，每次都要输一长串路径，烦死人。

三、怎么用：一步步装起来（Mac 版）

第 1 步：检查电脑基础条件

# 打开终端（Terminal），依次输入：
sw_vers              # 查看 macOS 版本（建议 12.0+）
xcode-select -p      # 查看 Xcode 命令行工具是否已安装
  • 如果 xcode-select -p 报错，先安装 Xcode（App Store 搜索 Xcode 安装，较大）或运行：
xcode-select --install

第 2 步：下载 Flutter SDK

  1. 打开官网：https://docs.flutter.dev/get-started/install/macos
  2. 下载最新的稳定版 SDK 压缩包（文件名类似 flutter_macos_xxx-stable.zip）。
  3. 也可以直接用终端下载（以 macOS ARM 版为例）：
# 把 SDK 下载到"下载"文件夹
cd ~/Downloads
curl -O https://storage.googleapis.com/flutter_infra_release/releases/stable/macos/flutter_macos_arm64_3.x.x-stable.zip

# 解压（如果下载的是 zip）
unzip flutter_macos_arm64_3.x.x-stable.zip

小贴士：如果官网/谷歌下载慢，可以用国内镜像（把下载地址换成 flutter 中国镜像站），或直接解压后配置镜像环境变量（见第 4 步）。

第 3 步：把 Flutter 放到合适的位置并配置 PATH

推荐把 Flutter 放到 ~/development 或 ~/flutter（你自己的目录，不要放系统目录）。

# 1. 创建目录并移动（假设解压在 ~/Downloads/flutter）
mkdir -p ~/development
mv ~/Downloads/flutter ~/development/flutter

# 2. 配置 PATH：把 flutter/bin 加进系统 PATH（写入配置文件 ~/.zshrc）
echo 'export PATH="$PATH:$HOME/development/flutter/bin"' >> ~/.zshrc

# 3. 让配置立即生效
source ~/.zshrc

# 4. 验证是否成功（看到版本号就说明装好了）
flutter --version

PATH 是什么？ 大白话：PATH 是系统的一张"寻人启事清单"，告诉终端"去哪里找命令"。加了 flutter/bin 之后，你在任何地方敲 flutter，终端都知道去 ~/development/flutter/bin 里找它。

第 4 步：配置国内镜像（可选，但强烈建议）

如果你在国内网络环境，Flutter 下载依赖很慢，配置镜像（以清华/腾讯镜像为例）：

# 追加到 ~/.zshrc
echo 'export PUB_HOSTED_URL=https://pub.flutter-io.cn' >> ~/.zshrc
echo 'export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn' >> ~/.zshrc
source ~/.zshrc

第 5 步：运行 flutter doctor 体检

flutter doctor

flutter doctor 就像"体检报告"，检查每个环节是否正常：

检查项 正常标志
Flutter 绿色 [✓] Flutter
Xcode 绿色 [✓] Xcode - develop for iOS and macOS
Chrome 绿色 [✓] Chrome - develop for the web
Android toolchain 没装安卓时是 [✗]，可先忽略

看到 [✗] 别慌，看它提示缺什么。通常 flutter doctor --android-licenses 或安装对应组件就能解决。

第 6 步：创建第一个项目

# 进入你想放项目的目录，比如桌面
cd ~/Desktop

# 创建 Flutter 项目（my_first_app 是项目名，必须小写+下划线）
flutter create my_first_app

# 进入项目目录
cd my_first_app

创建成功后项目里会有：
- lib/main.dart —— 你的主代码文件（以后主要写这里）
- pubspec.yaml —— 项目的"依赖清单"（相当于 Podfile）
- ios/、android/ 等 —— 各平台的"壳工程"（一般不用手动改）

第 7 步：启动模拟器并运行

方式 A：iOS 模拟器（推荐先跑这个）

# 打开 iOS 模拟器（需要已装 Xcode）
open -a Simulator

# 在项目目录里运行（首次编译较慢，耐心等）
flutter run

看到模拟器上出现一个默认计数器 App，就说明成功了！

方式 B：Chrome 网页版（最快，无需模拟器）

flutter run -d chrome

方式 C：列出所有可用设备

flutter devices   # 查看有哪些设备/模拟器可选
flutter run -d <设备ID>

第 8 步：把 Hello World 改成"自己的"

用 VS Code 或任何编辑器打开 lib/main.dart，把中间的核心部分替换成最简单的代码（下面的完整版可直接用）：

// lib/main.dart —— 第一个 Hello World
import 'package:flutter/material.dart';

// main 函数：App 的启动入口（相当于 iOS 的 main）
void main() {
  // runApp：把我们的根 Widget 交给 Flutter 渲染
  runApp(const MyApp());
}

// 定义一个 App（StatelessWidget：没有状态的静态页面）
class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    // MaterialApp：Material 风格的 App 外壳（提供主题、导航等）
    return MaterialApp(
      title: '我的第一个 App',
      // Scaffold：页面的"骨架"（相当于 UIViewController 的 view）
      home: Scaffold(
        // AppBar：顶部标题栏（相当于 UINavigationBar）
        appBar: AppBar(
          title: const Text('Hello Flutter'),
        ),
        // body：页面主体内容
        body: const Center(
          // Center：把子组件放到屏幕中间
          child: Text(
            'Hello World！我的第一个 Flutter App',
            style: TextStyle(fontSize: 24),  // 文字大小
          ),
        ),
      ),
    );
  }
}

保存文件后，回到运行 flutter run 的终端，按键盘 r 键（热重载），模拟器上的界面会立刻刷新成你的新内容。这就是 Flutter 最爽的"热重载"！

四、模拟器使用速查（小白版）

操作 命令 / 方法
打开 iOS 模拟器 open -a Simulator
查看所有设备 flutter devices
在 iOS 模拟器运行 flutter run（默认）或 flutter run -d ios

五、iOS 开发者视角（老司机对照表）

iOS 原生概念 Flutter 对应 大白话
Xcode 安装 Flutter SDK 安装 都是"装工具链"
创建 Xcode 工程 flutter create 生成工程骨架
Scheme / Target 项目内的 ios/android 壳工程 打包配置
AppDelegate / main main() + runApp() 启动入口
模拟器（iOS Simulator） 同样的 iOS 模拟器 一模一样，直接用
真机调试 flutter run 连接真机 需要开发者证书
Podfile pubspec.yaml 依赖管理文件
Xcode 编译 flutter build / flutter run 构建命令
热重载 r 键秒级刷新 原生没有的福利

给 iOS 工程师的提醒：
- 你电脑上已有的 Xcode 和 iOS 模拟器直接就能用，Flutter 会"借用"它们，不用额外装双份。
- pubspec.yaml 就是"Podfile + Package.swift"的角色，加依赖后要执行 flutter pub get（相当于 pod install）。
- 首次 flutter run 慢是正常的（要编译整个引擎 + 壳工程），第二次就快了。

六、小节小结

  1. 环境三件套：Flutter SDK + Xcode + 编辑器，缺一不可。
  2. 配置 PATH 后，flutter 命令随处可用；flutter doctor 是体检工具。
  3. flutter create 项目名 生成工程，flutter run 运行，r 键热重载。
  4. 第一个 App 的核心代码只有三件事：main() → runApp() → 一个 Widget 树。
  5. iOS 模拟器直接复用你已有的 Xcode 环境，无需额外折腾。
