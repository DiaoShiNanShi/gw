一、基础题（20 道）

1. Flutter 是什么？和 React Native 有什么区别？

  • 考察点：对 Flutter 本质的理解
  • 大白话答案：Flutter 是 Google 的跨平台 UI 框架，用 Dart 语言写一套代码，同时跑在 iOS/Android/Web/桌面。核心区别是渲染方式：Flutter 用自带的引擎（Skia/Impeller）自己画 UI，不经过系统原生控件；RN 是桥接原生控件（把 JS 组件翻译成原生 View）。所以 Flutter 渲染一致性强、性能接近原生，RN 更依赖平台控件、一致性和性能略差。
  • 加分项：能说出 Flutter "自绘引擎"的优势（跨端一致、不依赖平台控件更新）；RN 的桥接有性能损耗。

2. Dart 语言有哪些核心特性？

  • 考察点：Dart 基础
  • 大白话答案：面向对象（一切皆对象）、强类型（也支持类型推断 var/final/const）、单线程 + 事件循环（异步用 Future/async-await）、Isolate 并发（不共享内存）、空安全（?/! 语法）、支持 mixin 混入。
  • 加分项：提到空安全是 Dart 2.12 引入的，编译期就消灭空指针异常。

3. const 和 final 的区别？

  • 考察点：Dart 关键字
  • 大白话答案：final 表示"只能赋值一次"，运行时可确定；const 表示"编译期常量"，值在编译时就固定。const 比 final 更严格（const 变量也是 final 的）。
  • 代码示例：
final a = DateTime.now();   // 可以：运行时确定
// const b = DateTime.now(); // 报错：const 需要编译期常量
const c = 3.14;             // 编译期就固定了
  • 加分项：const 构造的 Widget 会被复用，是 Flutter 性能优化手段之一。

4. Flutter 的 StatefulWidget 和 StatelessWidget 区别？

  • 考察点：Widget 基础
  • 大白话答案：StatelessWidget 无状态，内容不变，build 一次就不变了；StatefulWidget 有状态（State 对象），可以 setState 触发重建。StatefulWidget 本体不可变，状态存在 State 里（State 跨帧存活）。
  • 加分项：StatefulWidget 和 State 是分开的两个类，Widget 重建时 State 不重建（Element 复用）。

5. Widget 生命周期有哪些？

  • 考察点：State 生命周期
  • 大白话答案：initState（创建，只一次）→ didChangeDependencies（依赖变化）→ build（构建，可多次）→ didUpdateWidget（父组件更新触发）→ deactivate（移出树）→ dispose（销毁，清理资源）。
  • 加分项：initState 里不能调 BuildContext 相关异步操作；资源（控制器/定时器）必须在 dispose 释放。

6. setState 做了什么？为什么要调用它？

  • 考察点：状态更新机制
  • 大白话答案：setState 标记当前 State 为"脏"，通知 Flutter 在下一帧重建 build 方法，刷新 UI。不调用它，数据变了界面不会更新。
  • 加分项：setState 只是"标记"，真正重建是下一帧；频繁 setState 可能性能问题，应缩小范围。

7. BuildContext 是什么？

  • 考察点：三棵树理解
  • 大白话答案：BuildContext 是 Element 的接口，代表 Widget 在树中的位置。用来向上/向下找祖先/后代、取主题（Theme.of）、路由（Navigator.of）、Provider 数据（context.watch）。
  • 加分项：能说出"BuildContext 本质是 Element 的瘦身版"，Widget 是描述、Element 是真实节点。

8. Flutter 三棵树是什么？为什么是"三棵"？

  • 考察点：底层原理（高频）
  • 大白话答案：Widget 树（描述/菜单）、Element 树（桥梁/服务员）、RenderObject 树（真实渲染/后厨）。Widget 重建便宜（只换描述），Element 复用（新旧对比 runtimeType+key），RenderObject 最小化更新（只重做变化部分），这套机制兼顾声明式写法和高性能。
  • 加分项：能说 canUpdate 判断条件（runtimeType 和 key 都相同才复用）。

9. key 的作用是什么？ValueKey/ObjectKey/UniqueKey 区别？

  • 考察点：Element 复用
  • 大白话答案：key 是 Element 复用的"身份标识"。列表增删、顺序变化时，没有 key 会导致状态错乱。ValueKey（值相等）、ObjectKey（对象相等）、UniqueKey（每次都不同，强制重建）。
  • 加分项：列表项需要稳定唯一 id 时用 ValueKey(id)，而不是用 index（会错乱）。

10. Row 和 Column 的区别？

  • 考察点：布局基础
  • 大白话答案：Row 水平排列子组件（主轴横向），Column 垂直排列（主轴纵向）。都有 mainAxisAlignment（主轴对齐）和 crossAxisAlignment（交叉轴对齐）。
  • 加分项：子组件过多溢出时用 Expanded/Flexible 包裹，避免 RenderFlex overflow 报错。

11. Expanded 和 Flexible 的区别？

  • 考察点：弹性布局
  • 大白话答案：都是让子组件按比例分配剩余空间。Expanded 强制占满分配的空间（flex 比例）；Flexible 允许子组件小于分配空间（fit: loose 时不强制填满）。
  • 加分项：Flexible 默认 loose，Expanded 相当于 fit: tight。

12. Stack 是什么？怎么用？

  • 考察点：层叠布局
  • 大白话答案：Stack 是层叠布局，子组件一层层叠放（后写的在上面），类似 iOS 的 ZStack。配合 Positioned 可以精确指定位置（top/left/right/bottom）。
  • 加分项：能举例子：头像右上角加"小红点"就是 Stack + Positioned。

13. ListView.builder 和 ListView 的区别？

  • 考察点：列表性能
  • 大白话答案：ListView(children: [...]) 一次性创建所有子项；ListView.builder 按需创建（滚动到哪建哪），适合大数据量。数据多必须用 builder。
  • 加分项：加 itemExtent 固定行高可进一步优化滚动性能。

14. Text 如何显示多行、省略号？

  • 考察点：文本组件
  • 大白话答案：maxLines 限制行数，overflow: TextOverflow.ellipsis 超出显示省略号。
  • 代码示例：
Text('很长很长的一段文字',
  maxLines: 1,
  overflow: TextOverflow.ellipsis,  // 超出省略
)

15. Image 加载网络图片用什么？要注意什么？

  • 考察点：图片加载
  • 大白话答案：Image.network(url) 直接加载；生产环境推荐 cached_network_image（带缓存）。注意：占位图/错误图（loadingBuilder/errorBuilder）、缓存策略。
  • 加分项：列表里大量图片用 cached_network_image 避免重复下载卡顿。

16. Navigator.push 和 Navigator.pushNamed 的区别？

  • 考察点：路由基础
  • 大白话答案：push 直接传 Widget 跳转；pushNamed 按"路由名"跳转（需先在 routes 表注册）。命名路由适合统一管理、可传参数。
  • 加分项：复杂项目用 go_router（支持深链、嵌套路由）。

17. 如何给页面传参数？如何回传结果？

  • 考察点：路由传参
  • 大白话答案：push 时第二个参数传参（构造器参数或 arguments）；回传用 Navigator.pop(context, result)，接收端 await Navigator.push(...) 拿返回值。
  • 加分项：能写出完整示例。

18. main() 里做了什么？

  • 考察点：入口
  • 大白话答案：runApp(MyApp()) 启动 App；可加 WidgetsFlutterBinding.ensureInitialized()（调用原生能力前），async 初始化（如读本地配置）再 runApp。
  • 加分项：解释 ensureInitialized 是"确保 Flutter 引擎和平台绑定初始化完成"。

19. 什么是 MaterialApp？它提供了什么？

  • 考察点：App 壳
  • 大白话答案：MaterialApp 是 Flutter 的"App 外壳"，提供：主题（theme）、路由表（routes）、本地化、标题、首页（home）。类似 iOS 里管理整个 App 的根控制器。
  • 加分项：能说出 Material 设计风格和 Cupertino（iOS 风格）的区别。

20. debugPrint 和 print 的区别？

  • 考察点：调试基础
  • 大白话答案：print 直接输出；debugPrint 在 debug 模式会截断超长输出（避免丢日志），release 模式两者都可被移除/禁用。
  • 加分项：生产环境用 kDebugMode 判断是否打印，避免日志泄露。

二、中级题（20 道）

21. 隐式动画和显式动画的区别？

  • 考察点：动画体系
  • 大白话答案：隐式动画（AnimatedContainer/AnimatedOpacity）只需声明"目标值"，Flutter 自动做过渡；显式动画（AnimationController + Tween）手动控制进度（forward/reverse/repeat）、精确到每帧。简单变化用隐式，复杂/循环/联动用显式。
  • 加分项：AnimationController 需要 vsync（TickerProviderStateMixin），用完必须 dispose。

22. Tween 的作用？

  • 考察点：动画
  • 大白话答案：Tween 是"翻译官"，把 AnimationController 的 0→1 进度翻译成具体值（0→300 像素、颜色渐变、角度旋转）。配合 CurvedAnimation 可加缓动曲线。
  • 加分项：能写 Tween(begin: 0, end: 300).animate(CurvedAnimation(...))。

23. Hero 动画是什么？怎么用？

  • 考察点：转场动画
  • 大白话答案：Hero 是页面间"共享元素"转场：两个页面各有一个相同 tag 的 Hero 包裹组件，跳转时元素自动"飞过去"。类似 iOS 的共享元素转场。
  • 加分项：tag 必须唯一且两端一致，否则不生效或报错。

24. 什么是 RepaintBoundary？什么时候用？

  • 考察点：性能优化
  • 大白话答案：RepaintBoundary 是"重绘隔离区"：里面的组件重绘不会带动外面重绘。适合：动画/进度条/频繁变化的小区域，避免带动整页重绘。
  • 加分项：能用 DevTools 的 Repaint Rainbow 定位重绘区域。

25. 如何优化列表性能？（说出至少 3 点）

  • 考察点：性能
  • 大白话答案：①用 ListView.builder 按需创建；②itemExtent 固定行高；③能 const 就 const；④图片缓存；⑤避免 itemBuilder 里做耗时操作；⑥用 RepaintBoundary 隔离重绘。
  • 加分项：提到 keepAlive（AddAutomaticKeepAlives）缓存滚出屏幕的条目。

26. 状态管理有哪些方案？各自的适用场景？

  • 考察点：状态管理（高频）
  • 大白话答案：setState（页面局部）、Provider（中小项目，易上手）、Riverpod（中大型，编译期安全、可测试）、Bloc（大型复杂业务，事件驱动、可追踪）、GetX（全家桶，简单但侵入性强）。选型：小项目 setState+Provider；中项目 Provider/Riverpod；大项目 Riverpod/Bloc。
  • 加分项：能对比 Provider 和 Riverpod（Riverpod 不依赖 BuildContext、编译期安全）。

27. Provider 的原理是什么？

  • 考察点：状态管理原理
  • 大白话答案：Provider 基于 InheritedWidget + ChangeNotifier。ChangeNotifier 持有数据，notifyListeners() 通知监听者；Provider 把 ChangeNotifier 放到 Widget 树上，context.watch<T>() 找到并监听，数据变化时自动重建依赖它的组件。
  • 加分项：watch 监听（build 里用）、read 不监听（事件里用）。

28. Future 和 Stream 的区别？

  • 考察点：异步
  • 大白话答案：Future 返回一个结果（一次性，如网络请求）；Stream 是连续多个结果的事件流（如传感器数据、进度条）。Future 用 await 拿值，Stream 用 listen 监听。
  • 加分项：能举例：网络请求用 Future，实时位置用 Stream。

29. async / await 的原理？

  • 考察点：异步原理
  • 大白话答案：async 函数返回 Future；await 会"暂停"当前函数，把后续代码当作回调，等 Future 完成后继续执行。底层是 Dart 单线程事件循环 + 微任务队列。
  • 加分项：能解释"Dart 是单线程，async/await 不会阻塞 UI"。

30. Dart 的事件循环（Event Loop）是什么？

  • 考察点：并发模型（重要）
  • 大白话答案：Dart 单线程靠事件循环驱动：一个"事件队列"（如 IO、定时器、点击），循环不断取事件执行。异步就是往队列里扔任务。微任务（microtask）优先于事件队列执行。
  • 加分项：能说出 Future 回调进微任务、Timer/IO 进事件队列，微任务先执行。

31. Isolate 是什么？和线程的区别？

  • 考察点：并发（高频）
  • 大白话答案：Isolate 是 Dart 的"隔离区"：每个 Isolate 有独立内存、独立事件循环，不共享内存，只能通过消息（SendPort/ReceivePort）通信。比线程安全（无数据竞争），但通信有开销。
  • 加分项：重活（大 JSON 解析、图片处理）用 compute / Isolate 跑，主 Isolate 只做 UI。

32. compute 函数怎么用？适合什么场景？

  • 考察点：并发
  • 大白话答案：compute(fn, data) 把函数丢到后台 Isolate 执行，返回 Future 结果。适合一次性重活：解析大 JSON、复杂计算、图片压缩。
  • 加分项：注意 compute 的函数必须是顶层/静态函数，不能闭包捕获。

33. 网络请求怎么做？常用的库？

  • 考察点：网络
  • 大白话答案：用 dio（最流行）或 http 包。dio 支持拦截器（加 token）、超时、取消、文件上传下载、错误处理。请求结果用 json_serializable 转 Model。
  • 加分项：能说出拦截器用法（日志拦截器、token 拦截器）。

34. JSON 序列化怎么做？

  • 考察点：数据解析
  • 大白话答案：手动 jsonDecode + fromJson/toJson；或用 json_serializable + build_runner 自动生成。复杂项目推荐自动生成，省事不易错。
  • 加分项：能写出 Model 的 fromJson/toJson 模板。

35. 本地存储有哪些方案？

  • 考察点：存储
  • 大白话答案：shared_preferences（键值对，小数据，≈UserDefaults）；sqflite/drift（SQLite 数据库，结构化大数据）；path_provider（文件存储）；hive（NoSQL 轻量库）。
  • 加分项：能按场景选型（登录态用 preferences，聊天记录用 sqflite）。

36. 如何实现"深色模式"？

  • 考察点：主题
  • 大白话答案：MaterialApp 的 themeMode（system/light/dark）+ darkTheme 配置；用 Theme.of(context).colorScheme 取色，别写死颜色。
  • 加分项：能监听系统主题变化（ThemeMode.system 自动跟随）。

37. 国际化怎么做？

  • 考察点：i18n
  • 大白话答案：MaterialApp 配 localizationsDelegates + supportedLocales；用 intl 包管理文案（arb 文件），AppLocalizations.of(context) 取翻译文案。
  • 加分项：提到 gen-l10n 自动生成本地化类。

38. 路由守卫/拦截怎么做？

  • 考察点：路由进阶
  • 大白话答案：命名路由用 NavigatorObserver 监听跳转做拦截；go_router 提供 redirect 做鉴权跳转（未登录跳登录页）。
  • 加分项：能写出"未登录拦截到登录页"的伪代码。

39. 如何监听 App 前后台切换？

  • 考察点：生命周期
  • 大白话答案：WidgetsBindingObserver + didChangeAppLifecycleState，状态有 resumed（前台）/paused（后台）/inactive 等。
  • 加分项：后台时暂停动画/保存草稿，回前台恢复。

40. GlobalKey 有什么用？

  • 考察点：进阶 Widget
  • 大白话答案：GlobalKey 可以跨组件访问 State：GlobalKey<FormState> 拿到表单校验/提交；也可以获取组件的位置尺寸（BuildContext）。
  • 加分项：能用 GlobalKey 获取组件 RenderBox 的 size/position（做引导蒙层）。

三、高级题（15 道）

41. 解释 Flutter 的渲染管线（pipeline）。

  • 考察点：底层原理（高频）
  • 大白话答案：每帧走：build（构建 Widget 树）→ layout（计算位置大小）→ paint（绘制）→ composite（合成图层）→ 上屏。任一阶段超过 16.7ms 就掉帧。优化 = 减少各阶段工作量（const、RepaintBoundary、避免主线程耗时）。
  • 加分项：提到"帧调度"由 vsync（Ticker）驱动，和 iOS 的 CADisplayLink 类似。

42. Element 复用的条件是什么？什么是 canUpdate？

  • 考察点：三棵树
  • 大白话答案：新旧 Widget 的 runtimeType 和 key 都相同，Element 就复用（不重建），只更新配置；否则销毁重建。这就是为什么列表项要加稳定的 key。
  • 加分项：能说 canUpdate 源码逻辑（runtimeType == 且 key ==）。

43. InheritedWidget 的原理是什么？

  • 考察点：状态共享底层
  • 大白话答案：InheritedWidget 是"向上共享数据的机制"：子组件通过 context.dependOnInheritedWidgetOfExactType<T>() 获取最近祖先的数据，且依赖它后，祖先数据变化会精确通知依赖者重建（不重建整棵树）。Provider 就是它的封装。
  • 加分项：updateShouldNotify 控制是否通知。

44. Dart 空安全是什么？?、!、late 各是什么？

  • 考察点：Dart 进阶
  • 大白话答案：空安全 = 编译期保证变量不会意外为空。String? 表示可空；! 断言"我确定不为空"；late 延迟初始化（首次使用时赋值，用于 late final 等）。?? 提供默认值。
  • 加分项：能举出 ! 用错的崩溃场景（空断言失败）。

45. 如何做内存泄漏排查？

  • 考察点：性能
  • 大白话答案：用 DevTools Memory 面板：反复进出页面看内存曲线是否回落；用 Allocation Profile 找堆积对象。常见泄漏：控制器/定时器/监听没 dispose、全局单例持有页面。
  • 加分项：能说出"只涨不跌 = 有泄漏"的判断方法。

46. const 优化原理是什么？

  • 考察点：性能
  • 大白话答案：const Widget 是编译期常量，Flutter 会缓存同一 const 实例。重建时直接复用同一个对象，跳过创建和比较，减少 build 开销。flutter analyze 会提示可加 const 的位置。
  • 加分项：能说出 const 对 Element 复用也有帮助（canUpdate 时配置相同跳过更新）。

47. 包体积如何优化？

  • 考察点：性能/发布
  • 大白话答案：①Tree Shaking（默认删无用代码）；②按需引包（别为小功能装大库）；③压缩图片资源（WebP）；④清理无用 assets；⑤Android 用 AAB 按架构分发；⑥iOS 检查 App Thinning。
  • 加分项：能说出 flutter build release 模式默认开启 AOT 和 Tree Shaking。

48. 启动速度如何优化？

  • 考察点：性能
