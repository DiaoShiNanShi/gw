高级 03：架构与性能优化——本地推理、llama.cpp、端侧 AI

高级模块

学习目标：搞懂"本地跑大模型"这件事的完整图景：用什么工具、为什么快、端侧 AI 是怎么回事。
读完这章，你能理解自己电脑上跑 AI 的每一步在干什么。

1. 本地推理引擎：谁在帮你跑模型？

大白话：推理引擎 = 负责把模型文件"加载进内存、跑推理、吐文字"的软件。你下载的模型不会自己跑，需要一个"引擎"来驱动。

主流本地推理引擎对比：

引擎 平台 特点 适合谁
llama.cpp 全平台 纯 C++ 实现，超轻量，CPU 也能跑，GGUF 格式鼻祖 追求极致性能和命令行玩家
Ollama 全平台 基于 llama.cpp，一键安装、命令简单，自动管理模型 新手首选
LM Studio 全平台 图形界面，点鼠标就能用，自带模型下载 完全不想碰命令行的
MLX Apple Silicon 专属 苹果官方框架，专门优化 M 系列芯片 Mac 用户进阶首选
llama.cpp + llama-server 全平台 llama.cpp 自带 HTTP 服务 想自己写代码调 API

示例（你的 Mac M2 上跑 7B 模型的速度参考）
- Ollama / llama.cpp：约 10~20 token/秒（打字速度的 2~3 倍，流畅）
- MLX：同模型还能再快一些，因为专门为 Apple Silicon 优化

2. llama.cpp 为什么是"本地之王"？

大白话：llama.cpp 把"在普通电脑上跑大模型"这件事做到了极致轻量。

  • 纯 C/C++ 编写，不依赖 Python 和重型框架
  • 内存占用极小，笔记本都能跑
  • 支持 CPU 推理（没独显也能用）
  • GGUF 格式的创造者（就是它定义了量化格式标准）
  • 手机、树莓派都能跑小模型

它怎么做到快的？
1. 极致的内存优化（mmap 直接映射模型文件，省内存）
2. 自动选择最优计算后端（CPU 用 AVX/NEON 指令集、Apple Silicon 用 Metal GPU）
3. 支持 KV Cache、Flash Attention 等全部优化
4. 量化后的模型直接读，无需解压

3. 端侧 AI（On-device AI）：AI 装进手机/电脑

大白话：端侧 AI = 不联网、不靠云端，直接在你自己设备上跑大模型。手机上的 AI 助手、你的 Mac 本地模型，都属于端侧 AI。

对比 云端 AI 端侧 AI
数据 发到服务器 不出设备，隐私安全
速度 受网络影响 本地即时响应
成本 按调用付费 一次买断，免费使用
能力 大模型（几百亿参数） 小模型（0.5B~8B，受硬件限制）
断网 用不了 离线可用

端侧 AI 的应用场景：
- 输入法 AI 助手（苹果、百度、搜狗都在做）
- 手机语音助手（Siri 本地化）
- 智能家居、车载语音
- 隐私敏感场景（医疗、金融）
- 你之前分析的 ITPhone 项目（SwiftUI + 本地 LLM）就是典型端侧 AI

Apple Silicon 的端侧优势：
- 统一内存：CPU 和 GPU 共享 16GB 内存，模型参数直接放内存里，CPU/GPU 都能访问，不用来回拷贝——这是 Mac 跑大模型比普通 Windows 笔记本快的重要原因
- Metal GPU：苹果自家 GPU 加速 API
- MLX 框架：苹果官方为 AI 专门推出的框架，对 M 系列芯片深度优化

4. MLX：Mac 上训练和跑模型的最佳选择

大白话：MLX = 苹果官方出的"AI 计算框架"，专门给 Apple Silicon 优化。想在 Mac 上做正经的 AI 开发，用 MLX 比 PyTorch 更快更省内存。

示例（M2 16GB 上用 MLX 能干什么）
- 跑 Qwen2.5-7B（4bit 量化）：流畅对话
- 微调小模型（LoRA）：几分钟就能跑一轮
- 跑各种 HuggingFace 上的 MLX 版模型：几乎全覆盖

安装就一句话：
bash pip install mlx-lm
用起来也简单：
bash python -m mlx_lm.generate --model Qwen/Qwen2.5-1.5B-Instruct-4bit

5. 硬件常识：跑模型到底吃什么配置？

大白话：跑大模型最看重的不是 CPU 多强，而是"内存多大、内存多快"。因为模型参数要整个装进内存，每生成一个字要把全部参数读一遍。

配置 能流畅跑 说明
8GB 内存 ≤ 3B 量化模型 模型 2GB 以内才舒服
16GB 内存 ≤ 7B 量化模型 模型 4~5GB 以内流畅（你的配置）
32GB 内存 13B~14B 量化模型 模型 8~10GB
64GB+ 30B 以上模型 大内存的春天
专业显卡 24GB 显存 70B 量化 但要买得起

示例（你的 Mac M2 16GB）
- ✅ Qwen2.5-1.5B、7B（Q4）→ 流畅
- ✅ Llama 3.2-3B → 流畅
- ⚠️ 13B（Q4 约 8GB）→ 能跑但很慢、内存告急
- ❌ 70B → 内存直接不够

经验法则：模型文件大小不要超过内存的 1/3~1/2。16GB 内存 → 模型别超过 5GB（即 7B Q4 就是上限了）。

6. 生成速度怎么算出来的？

大白话：每生成一个字，都要把模型的全部参数"读"一遍。所以速度 ≈ 内存带宽 ÷ 参数量。

你的 M2 内存带宽约 100GB/s
7B Q4 模型 = 约 4.5GB
理论速度 ≈ 100 ÷ 4.5 ≈ 22 token/秒

（实际还要扣除各种开销，大约 10~15 token/秒，依然流畅）

这就是为什么：
- 模型越小、量化越狠 → 越快
- 内存带宽越大的芯片 → 越快（M 系列 Pro/Max/Ultra 更快就是因为带宽大）

小结（本地跑模型的完整链条）

下载 GGUF 模型文件（已量化，几百 MB~几 GB）
  → 用 Ollama / llama.cpp / MLX 加载进内存
  → CPU/GPU 用矩阵乘法做推理（KV Cache + Flash Attention 加速）
  → 一个字一个字吐出来（流式输出）
  → 配合 RAG 能查资料、配合 LoRA 能微调定制
