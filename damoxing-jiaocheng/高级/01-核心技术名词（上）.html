高级 01：核心技术名词（上）——矩阵、量化、GGUF、采样

高级模块

学习目标：搞懂技术文章里最常出现的 4 组硬核名词，从此能看懂 80% 的 AI 技术帖。
大白话原则不变：每个名词都配比喻和例子。

1. 矩阵乘法（Matrix Multiplication）：GPU 存在的意义

大白话：矩阵乘法 = 把一张"数字表格"和另一张"数字表格"按规则相乘，得到一张新表格。大模型的所有计算，本质上都是海量的矩阵乘法。

大模型的参数是表格（矩阵），输入的文字也是表格。让模型"思考"，就是不断地让这些表格相乘。

示例
输入向量（1 行 4 列） 参数矩阵（4 行 3 列） 输出（1 行 3 列） ┌─────────────┐ ┌───────────────┐ ┌───────────────┐ │ 0.5 0.2 1.0 │ × │ 0.1 0.3 0.7 │ │ 0.25 0.95 1.1 │ │ 0.4 0.8 0.6 │ │ 0.2 0.6 0.9 │ = │ ... │ └─────────────┘ └───────────────┘ └───────────────┘
模型越大，矩阵越大，乘法次数越多。一次 70B 模型的推理，要做的矩阵乘法次数是个天文数字（10 的 18 次方级别）。

为什么 GPU 快？

CPU GPU
比喻 一个天才博士 一万个普通工人
特点 单核极强，但核少（8~16 核） 单核弱，但核极多（几千上万个核）
适合 逻辑复杂、步骤分明的任务 大量重复、可并行的计算
跑大模型 慢（一次只能算一个数） 快（几千个核同时算不同的数）

矩阵乘法极度适合并行：每个格子之间互不干扰，可以同时算。GPU 几千个核一起上，所以大模型必须在 GPU 上跑才快。

2. 量化（Quantization）：给模型"减肥"

大白话：量化 = 把参数从"高精度数字"降级成"低精度数字"，从而大幅减小体积、降低内存占用，代价是稍微损失一点精度。

模型参数默认是 FP16（16 位浮点数，占 2 字节）。量化就是把它压缩：

量化级别 每个参数占 体积对比（以 7B 模型为例） 效果
FP16（原始） 2 字节 约 14GB 精度最高，吃内存
INT8 / Q8 1 字节 约 7GB 几乎无损
INT4 / Q4 0.5 字节 约 3.5~4GB 轻微损失，肉眼几乎不可见
INT2 / Q2 0.25 字节 约 1.75GB 明显变笨，不推荐

示例
你之前看到的 Qwen2.5-0.5B Q4_K_M.gguf：
- 0.5B 参数原始 FP16 = 约 1.0GB
- Q4 量化后 ≈ 0.4GB（400MB）
- 少了 60%，智商只下降一点点——这就是量化的魅力。

相关名词：
- Q4_K_M：Q4 = 4 位量化；K = K-quant 量化方法；M = 中间档位（还有 S 小档、L 大档，M 是平衡档，最常用）。
- GGUF 里的量化：GGUF 文件里直接打包了量化好的参数，下载即用，不用自己量化。

3. GGUF：大模型的一种"打包格式"

大白话：GGUF 就像 ZIP 压缩包，把模型的参数、词表、配置信息打包成一个文件，让 llama.cpp 这类推理引擎能直接加载运行。

  • 格式：GGUF（GPT-Generated Unified Format）
  • 谁在用：llama.cpp、Ollama、LM Studio 等本地推理工具
  • 为什么重要：不同框架格式不通用（PyTorch 的 .bin/.safetensors、GGUF、MLX 的 .npz），GGUF 是本地部署最主流的格式

示例
下载模型时你会看到两种常见格式：
Qwen2.5-0.5B-Instruct-GGUF/Qwen2.5-0.5B-Instruct-Q4_K_M.gguf ← 本地部署用这个 Qwen2.5-0.5B-Instruct/safetensors（一堆文件） ← PyTorch 训练用

4. 采样策略：Top-K / Top-P / Temperature

前面讲过"按概率抽签选下一个字"，但直接按原始概率抽，容易抽到明显不合理的冷门字。所以工程上用 Top-K 和 Top-P 把候选范围先砍小，再抽签。

示例
模型算出下一个字的概率表：
"好" 35% "棒" 20% "吗" 15% "看" 8% "啊" 5% "的" 4% "了" 3% "香蕉" 0.5% ...

策略 规则 上例效果
Top-K 只保留概率最高的 K 个字 K=5 → 候选剩 [好 棒 吗 看 啊]
Top-P 按概率从高到低累加，直到总和超过 P，只保留这些 P=0.9 → 累加 [好35+棒20+吗15+看8+啊5+的4+了3=90%] → 候选剩 7 个
Temperature 调整整体随机性 低温度 → 好更容易被选中；高温度 → 香蕉也可能被选中

实际应用中的组合拳：

Top-P = 0.9  （先砍掉明显不合理的）
Temperature = 0.7 （再调随机程度）
  • 写代码、写事实类回答：Temperature 调低（0.1~0.3），要准确
  • 写故事、头脑风暴：Temperature 调高（0.8~1.2），要有创意

5. 幻觉（Hallucination）：AI 一本正经地胡说八道

大白话：幻觉 = 模型一本正经、语气坚定地编造出根本不存在的事实。它不是在"骗你"，它是在"猜"，猜错了而已。

为什么会有幻觉？
1. 模型本质是"猜下一个字"，不是查数据库
2. 训练数据本身就有错误信息
3. 模型不知道"自己不知道"，它没有这个意识
4. 温度太高时，更容易瞎编

示例
你问："李白的手机号是多少？"
模型可能一本正经答："李白的手机号是 138-xxxx-xxxx，他喜欢用 iPhone。"
——全是编的。李白是唐朝人，根本没有手机。

你问："《红楼梦》的作者是谁？"（它有把握）
模型答："曹雪芹。"（正确）

关键在于：这两种回答，模型内部的"自信程度"其实没法区分——它没有"我确定/我不确定"的意识。

怎么减少幻觉？
- 用 RAG：先检索真实资料，再让模型基于资料回答（见高级 02）
- 降低 Temperature
- 提示词里加"如果你不确定，请直接说不知道"
