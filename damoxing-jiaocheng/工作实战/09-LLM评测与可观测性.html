工作实战 09：LLM 评测与可观测性（怎么知道 AI 好不好）

工作实战模块

学习目标：上线不是终点——要知道 AI 答得好不好、慢不慢、贵不贵。
大白话：评测 = 考试；可观测性 = 给 AI 装仪表盘。

1. 为什么要评测？

不评测的后果例子
Prompt 改坏了不知道上线新版本后用户投诉变多
RAG 召回变差文档更新了但检索还搜旧片段
成本悄悄暴涨某个接口 Token 用量翻倍

2. 三层评测体系

层级测什么工具/方法
模型层通用智商、代码、推理MMLU、HumanEval、C-Eval
应用层你的 Prompt + RAG 效果自建测试集、RAGAS、DeepEval
线上层真实用户满意度点赞率、人工抽检、A/B 测试

3. RAG 专项评测（RAGAS 思路）

# 简化版 RAG 评测逻辑（理解指标即可，生产可用 ragas 库）
test_cases = [
    {"question": "年假几天？", "expected_contains": "5天", "context": "入职满1年享5天年假"},
    {"question": "报销流程？", "expected_contains": "发票", "context": "附发票，经理审批"},
]

def eval_rag(question, answer, context):
    # faithfulness：答案是否忠于检索内容（不能瞎编）
    faithful = all(word in answer or word in context for word in question.split()[:2])
    # relevancy：答案是否切题
    relevancy = len(answer) > 10 and "不知道" not in answer
    return {"faithful": faithful, "relevant": relevancy}

for case in test_cases:
    # 模拟：你的 RAG 系统返回答案
    fake_answer = "入职满1年享5天年假"
    print(case["question"], eval_rag(case["question"], fake_answer, case["context"]))

4. 可观测性：Trace + 指标

每次 AI 调用应记录：

  • request_id、用户 id、模型名、Prompt Token、Completion Token、延迟 ms、是否报错
  • RAG 额外记录：检索到的 doc_id、相似度分数

常用工具：Langfuse、LangSmith、Helicone、自建 ELK + Prometheus。

# 最小化日志示例
import time, json, logging
log = logging.getLogger("llm")

def call_llm(messages):
    t0 = time.time()
    # ... 调 API ...
    latency = (time.time() - t0) * 1000
    log.info(json.dumps({
        "event": "llm_call", "latency_ms": latency,
        "prompt_tokens": 120, "completion_tokens": 80, "model": "deepseek-chat"
    }))

5. CI 里跑评测（防退化）

  1. 维护 eval_set.jsonl（50~200 条业务问答 + 标准答案要点）
  2. 每次改 Prompt / 换模型 → CI 跑一遍 → 通过率低于 90% 则阻断合并
  3. 每周定时跑全量评测，出报告

小结

  1. 模型评测看 MMLU 等；业务评测看自建测试集 + RAGAS
  2. 线上必须打日志：延迟、Token、错误率
  3. 改 Prompt 必跑评测，别靠感觉
