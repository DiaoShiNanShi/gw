工作实战 04：Agent 智能体与 Function Calling（让 AI 自己干活）

工作实战模块

学习目标：掌握 2025-2026 年最火的 AI 技术——Agent（智能体）。
一句话：RAG 让 AI "知道"，Agent 让 AI "做到"。
会写 Agent 的人，现在是市场上最缺的 AI 工程师。

1. Agent 是什么（大白话）

Agent = 给 AI 装上"手"（能调用工具）和"脑"（能规划步骤），让它自己完成任务，而不是一问一答。

对比：
普通 AI（一问一答）：你问"明天天气"→ AI 说"我无法获取实时数据" Agent（会干活）：你问"明天天气"→ AI 自己调用天气 API → 拿到数据 → 回答你

Agent 的三大能力：
1. 规划：把大目标拆成小步骤（先查 A，再算 B，最后写 C）
2. 行动：调用外部工具（API、数据库、代码、浏览器）
3. 反思：看到结果后决定下一步（结果不对就换方案）

2. Function Calling（工具调用）——Agent 的地基

大白话：Function Calling = 告诉 AI "你手里有哪些工具、每个工具怎么用"，AI 自己决定什么时候用哪个工具。

流程：

用户："帮我查一下北京明天天气，热的话提醒我带伞"
    │
    ▼
AI 思考：我需要调用 get_weather(北京, 明天)
    │
    ▼
API 返回：{"tool_call": "get_weather", "arguments": {"city": "北京"}}
    │  （注意：此时 AI 没有直接回答，它是在"申请调用工具"）
    ▼
你的程序：真正执行 get_weather("北京")，拿到 {"温度": 32, "晴"}
    │
    ▼
把结果回传给 AI："工具返回：温度32度，晴天"
    │
    ▼
AI 最终回答："北京明天 32 度，记得带伞！"

关键理解：AI 不真正执行工具，它只"申请"调用工具，执行的是你的代码。 这样安全可控。

3. Function Calling 代码实战（Python）

"""
用 DeepSeek 的 Function Calling 实现"天气查询助手"
安装：pip install openai
"""
import json
from openai import OpenAI

client = OpenAI(api_key="sk-你的key", base_url="https://api.deepseek.com")

# 第 1 步：定义工具（告诉 AI 有哪些函数可用）
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询指定城市当天的天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名，如北京"},
                    "date": {"type": "string", "description": "日期，格式 YYYY-MM-DD，默认今天"},
                },
                "required": ["city"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "add_reminder",
            "description": "添加提醒事项",
            "parameters": {
                "type": "object",
                "properties": {
                    "content": {"type": "string", "description": "提醒内容"},
                    "time": {"type": "string", "description": "提醒时间，如 08:00"},
                },
                "required": ["content", "time"],
            },
        },
    },
]

# 第 2 步：模拟真实函数（真正干活的是你写的代码）
def get_weather(city, date="今天"):
    # 实际项目里这里调天气 API
    return {"city": city, "date": date, "temp": 32, "weather": "晴", "tip": "建议带伞"}

def add_reminder(content, time):
    # 实际项目里这里存数据库/发推送
    return {"ok": True, "content": content, "time": time}

def run_tool(name, args):
    """工具分发器"""
    if name == "get_weather":
        return json.dumps(get_weather(**args), ensure_ascii=False)
    if name == "add_reminder":
        return json.dumps(add_reminder(**args), ensure_ascii=False)
    return "未知工具"

# 第 3 步：主循环（Agent 的核心逻辑）
messages = [{"role": "user", "content": "帮我查下北京明天的天气，如果超过30度就提醒我明天8点带伞"}]

# AI 第一轮：它可能要求调用工具
resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=messages,
    tools=tools,          # ← 告诉 AI 有哪些工具
)

msg = resp.choices[0].message

# 判断 AI 是否申请调用工具
if msg.tool_calls:
    messages.append(msg)  # 把 AI 的"申请"加入历史
    for tool_call in msg.tool_calls:
        name = tool_call.function.name
        args = json.loads(tool_call.function.arguments)
        result = run_tool(name, args)
        # 把工具执行结果回传给 AI
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": result,
        })
    # 第二轮：AI 拿到工具结果后，给出最终回答
    final = client.chat.completions.create(
        model="deepseek-chat", messages=messages, tools=tools
    )
    print(final.choices[0].message.content)
else:
    print(msg.content)

这就是 Agent 的最小实现：定义工具 → AI 申请 → 你执行 → 回传结果 → AI 总结。循环多次就是复杂 Agent。

4. ReAct 模式：让 Agent "想一步做一步"

大白话：ReAct = AI 每做一步都"自言自语"推理，再行动，像人一样边想边做。

Thought: 用户要查天气，我需要调用 get_weather 工具
Action: get_weather("北京")
Observation: {"temp": 32, "weather": "晴"}
Thought: 32度超过30度了，用户要求提醒带伞，现在调用 add_reminder
Action: add_reminder("带伞", "08:00")
Observation: {"ok": true}
Thought: 都完成了，可以总结了
Answer: 北京明天32度晴天，已设置8点提醒你带伞！

工程上：很多框架（LangGraph、Dify）已经封装好了 ReAct，你只需要定义工具。

5. MCP（Model Context Protocol）——工具生态的 USB-C 接口

大白话：MCP = 一套统一标准，让任何 AI 都能即插即用地调用任何工具。以前每家 AI 都要单独写适配，现在按标准接就行。

类比 说明
USB-C 接口 统一了充电口，什么设备都能插
MCP 统一了 AI 工具接口，什么模型都能用

MCP 的实用价值（工作中）：
- 给 AI 接数据库（查订单、查库存）
- 给 AI 接公司内部系统（CRM、OA）
- 给 AI 接浏览器（让它自己上网查资料）
- 给 AI 接文件系统（读写文件）

示例：MCP 服务器（你的代码，暴露给 AI 用）
你写一个 Python 程序：查订单数据库（输入订单号 → 输出订单状态） 把它包成 MCP server → 任何支持 MCP 的 AI 客户端（Claude、Cursor、各类 Agent 平台） 都能直接调用它，无需为每家单独适配。

学习 MCP 建议：官方文档（modelcontextprotocol.io）+ 装一个 MCP server 跑通试试。

8. Agent 开发的坑（真实经验）

坑 现象 解法
工具调用循环 AI 反复调用同一工具 设最大轮数（如 5 轮）强制停止
参数幻觉 AI 编造工具参数 工具 schema 写详细描述；校验参数
权限过大 AI 调了不该调的工具 最小权限原则；高危工具单独确认
上下文爆炸 多轮工具结果把窗口塞满 工具结果压缩/截断
结果不可信 AI 声称"已完成"实际没做 工具返回必须带可验证的凭证

安全红线（重要）：Agent 能调用工具 = 有"手"，必须做好权限管控：
- 只暴露必要的工具（最小权限）
- 破坏性操作（删数据/转账）需要人工确认
- 所有工具调用记日志，可审计

小结

  1. Agent = 规划 + 调用工具 + 反思，本质是"循环调用 Function Calling"
  2. Function Calling 是地基：AI 申请工具，你的代码执行，结果回传
  3. MCP 是工具生态标准，未来所有 AI 应用都会支持
  4. 框架：开发者用 LangGraph，快速落地用 Dify/Coze
  5. 安全：给 AI 装手的同时必须装笼子（权限 + 日志 + 人工确认）
