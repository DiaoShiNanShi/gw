工作实战 05：微调实战（用你的数据定制模型）

工作实战模块

学习目标：掌握微调的完整流程：什么时候该微调、数据怎么准备、LoRA 怎么跑、效果怎么评估。
微调 = 给模型"补课"，教它你行业的专属知识或专属风格。

1. 什么时候该微调？（决策树）

需求 → 模型不知道？ → RAG（查资料）
     → 模型不会做？ → Prompt 试试 → 还不行 → 微调
     → 要专属风格/人设？ → System Prompt 试试 → 还不行 → 微调
     → 要更准/更快/更便宜？ → 微调小模型替代大模型

微调的 4 个典型场景：
1. 风格定制：让模型说话像你的品牌（"像董宇辉一样带货"）
2. 格式定制：让模型严格输出你公司的表单格式
3. 小模型替代大模型：用 7B 微调做到接近 70B 的效果 → 省 10 倍成本
4. 领域能力：法律文书、医疗术语、代码规范等专业领域

什么时候不该微调：
- 只是"模型不知道某个信息"→ 用 RAG
- 数据少于几百条 → 效果不明显，先用 Prompt
- 需要频繁更新知识 → 用 RAG

2. 微调的数据准备（决定 80% 的效果）

微调的本质：给模型喂"你希望它怎么回答"的例子。

对话格式（主流格式）

{"messages": [{"role": "user", "content": "推荐一款适合新手的咖啡"}, {"role": "assistant", "content": "推荐挂耳咖啡，不用买设备，热水一冲就能喝，最适合新手入门。"}]}
{"messages": [{"role": "user", "content": "手冲咖啡难吗？"}, {"role": "assistant", "content": "不难，只要掌握水温90度、粉水比1:15，多练几次就能稳定出品。"}]}

数据质量规则（记住这 5 条）

规则 说明
宁少勿滥 500 条高质量 > 5000 条凑数
一条一意 每条回答聚焦一个问题，别让模型学跑偏
多样性 覆盖不同问法、不同场景，别全是一个句式
干净无错 有错别字/错误知识的数据会教坏模型
标注来源 数据从哪来的记清楚，避免版权/隐私问题

数据清洗脚本

"""清洗训练数据：去重、去空、过滤超长"""
import json

def clean_data(input_path, output_path, min_len=10, max_len=2048):
    seen = set()
    cleaned = []
    with open(input_path, encoding="utf-8") as f:
        for line in f:
            try:
                item = json.loads(line)
                text = json.dumps(item, ensure_ascii=False)
                if text in seen:
                    continue
                # 过滤过短/过长
                if len(item["messages"][-1]["content"]) < min_len:
                    continue
                if len(text) > max_len:
                    continue
                seen.add(text)
                cleaned.append(item)
            except Exception:
                continue
    with open(output_path, "w", encoding="utf-8") as f:
        for item in cleaned:
            f.write(json.dumps(item, ensure_ascii=False) + "\n")
    print(f"清洗完成：{len(cleaned)} 条")

3. LoRA / QLoRA 实战（你的 M2 16GB 能跑）

你的配置建议微调 0.5B~3B 的小模型，7B 也能跑但要耐心（或先量化）。

方式一：MLX 微调（Apple Silicon 首选，推荐）

# 安装
pip install mlx-lm

# 准备数据 train.jsonl（上面格式）
# 训练（0.5B 模型，16GB 内存约 15~30 分钟）
python -m mlx_lm.lora \
  --model Qwen/Qwen2.5-0.5B-Instruct-4bit \
  --train \
  --data ./train.jsonl \
  --iters 300 \
  --batch-size 4 \
  --learning-rate 1e-5 \
  --adapter-path ./my-adapter

# 测试微调效果
python -m mlx_lm.generate \
  --model Qwen/Qwen2.5-0.5B-Instruct-4bit \
  --adapter-path ./my-adapter \
  --prompt "你的测试问题"

# 合并 LoRA 到完整模型（可选，部署用）
python -m mlx_lm.fuse --model Qwen/Qwen2.5-0.5B-Instruct-4bit --adapter-path ./my-adapter

4. 训练参数怎么看、怎么调

参数 作用 新手推荐
learning_rate 学习步长 1e-5（太大了学飞，太小了学不动）
iters / epochs 训练轮数 先 300 iters 试水，看 loss
batch_size 一次喂几条 4~8（内存允许范围内）
adapter_path LoRA 保存位置 独立文件夹

训练中看什么？
- loss（损失）：训练时打印，从 1.x 降到 0.5 以下说明在学
- 如果 loss 不降 → 学习率太大/数据太乱
- 如果 loss 降到 0.1 以下 → 可能过拟合（背答案了，换新问题就废）

5. 过拟合（背答案）怎么判断

大白话：模型把训练数据"背"下来了，而不是"学会"了。

现象：
- 训练集问题回答 100 分
- 换一个"同类型但没见过"的问题 → 答得稀烂

类比：学生把练习册答案背下来了，考试出同一本练习册的原题满分，换道新题就不会。

防过拟合：
1. 训练数据够多样
2. 训练轮数别太多
3. 用验证集监控（每轮看验证集 loss，涨了就停）

6. 微调效果评估（别凭感觉）

方法 说明
测试集问答 留 20% 数据不训练，训练完测这 20%
A/B 对比 同一批问题，微调前 vs 微调后，人工打分
自动化评测 用 GPT-4/DeepSeek 当裁判，给两版回答打分
业务指标 客服场景看"问题解决率"，代码场景看"通过率" 
"""用 LLM 当裁判评估微调效果"""
from openai import OpenAI
client = OpenAI(api_key="sk-你的key", base_url="https://api.deepseek.com")

def evaluate(before, after, question):
    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "system", "content": """你是严格评委。对比两个回答，从"准确性、风格符合度、完整性"打分(1-10)，输出JSON：{"before": 分数, "after": 分数, "reason": "一句话理由"}"""},
                  {"role": "user", "content": f"问题：{question}\n微调前：{before}\n微调后：{after}"}],
        response_format={"type": "json_object"},
    )
    return resp.choices[0].message.content

7. 微调 vs RAG vs Prompt（终极对比）

Prompt RAG 微调
成本 最低 中 高
见效速度 立刻 1~2 天 1~2 周
适合 调整语气/格式 注入新知识 学会新能力/风格
维护 改文字 改文档 重训练
代码量 无 中 多
工作优先级 先试 次之 最后

小结

  1. 决策：Prompt → RAG → 微调，微调是最后手段
  2. 数据决定成败：宁少勿滥、一条一意、干净多样
  3. 工具：Mac 用 MLX，有 N 卡用 LLaMA-Factory
  4. 盯 loss 防过拟合：验证集 + 控制轮数
  5. 评估：测试集 + A/B 对比 + LLM 裁判，别凭感觉
