iOS 逆向 04：逆向实战案例与合规边界

iOS 逆向模块

⚠️ 合规第一：逆向他人 App 用于破解内购、窃取数据、绕过鉴权 → 违法。本章案例仅限自有 App 安全自检。

1. 实战：审计 AI App 的 Key 是否泄露

  1. Archive 导出 IPA，解压看二进制
  2. Strings 搜索 sk-、api.、deepseek
  3. Frida Hook Keychain 读取、网络层 Authorization 头
  4. 若 App 内能直接看到 Key → 必须改架构（走服务端中转）
// Frida：打印所有带 Authorization 的请求头（自有 App 测试）
Interceptor.attach(ObjC.classes.NSURLRequest["- allHTTPHeaderFields"].implementation, {
    onLeave: function(retval) {
        var dict = new ObjC.Object(retval);
        console.log(dict.toString());
    }
});

2. 实战：Hook 自己的加密函数

若 App 对本地缓存的聊天记录做了加密，Hook 加解密函数确认密钥来源和强度。

3. 签名与重打包（概念）

  • iOS 每个 App 必须有效签名才能运行
  • 改 binary 后需用开发者证书重签：codesign -f -s "iPhone Developer" YourApp.app
  • 非越狱机只能装自己的开发证书签的包

4. 和大模型工程师的关系

逆向能力AI 工程价值
会看 Mach-O / Strings快速发现 Key 泄露、Prompt 硬编码
会 Frida Hook 网络验证服务端鉴权是否可 bypass
懂加固知道端侧模型文件如何防提取

5. 合法学习资源

  • Apple 官方 Security Guide、LLDB 文档
  • iOS App Reverse Engineering（社区电子书）
  • CTF 移动安全题（合法靶场）
  • 对自己 App 做渗透测试报告

小结

  1. 逆向核心技能：砸壳 → 静态分析 → 动态 Hook
  2. AI 工程师最该用逆向查自己的 App有没有 Key/Prompt 泄露
  3. 未经授权分析竞品有法律风险，别碰红线
